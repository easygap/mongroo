# 의상 레이어 v1 — 무착의형 원형 계약

캐릭터를 겹으로 나눠, 어떤 의상을 새로 만들어도 아래 레이어가 비치지 않게 하는
규격이다. 핵심은 **베이스에 옷을 그리지 않는 것**이다.

```text
base    맨살·얼굴·머리·식물 모티프 + 엔벨로프 안의 최소 가림
outfit  구매한 의상 + 그 의상의 신발·소품
inner   (선택) 기본 속옷 룩을 따로 보여줄 때만. 지금은 만들지 않는다
```

"무착의"는 나체가 아니라 **의상 디자인이 없는 상태**를 뜻한다. 베이스에도 가슴
부터 배꼽까지의 최소 가림은 남는다. 다만 그 가림이 아래의 커버리지 엔벨로프
안에 있고 피부에 가까운 색이라서, 어떤 옷을 입혀도 옷처럼 비치지 않는다.

렌더 순서는 `base → (inner) → outfit`이고, 한 캐릭터의 모든 레이어는 **같은
크롭·스케일·바닥선**을 공유한다.

## 왜 바꾸는가

v1 초판의 `body/` 시트는 캐릭터에게 진회색 탱크톱과 반바지를 그려 넣은
**착의형**이었다. 실측하면 이 옷은 인물 키를 1로 봤을 때

| 캐릭터 | 넥라인 | 밑단 |
|---|---|---|
| handsome-pot | 0.17 | 0.52 |
| pretty-pot | 0.20 | 0.48 |
| tsundere-pot | 0.17 | 0.53 |

를 차지한다. 즉 **목 아래부터 허벅지 중간까지**가 이미 옷으로 채워져 있다.
이보다 조금이라도 덜 덮는 옷(파인 목선, 오프숄더, 민소매, 슬릿, 짧은 밑단)을
입히면 그 진회색이 그대로 새어 나온다. 피부색과 명도 차가 커서 1px만 보여도
바로 눈에 띈다.

앱이 `skin_override` 플래그와 `{form}-skin.webp` 덧칠 파일을 갖고 있던 이유가
이것이다. 베이스가 착의형인 한 의상마다 피부를 다시 칠해 가려야 했고, 그래서
의상 시트가 손·목·다리 같은 신체를 포함하게 됐다. 신체가 의상 소유가 되면
의상을 바꿀 때마다 피부톤과 팔다리 실루엣이 함께 바뀐다.

무착의형 베이스는 이 사슬을 끊는다. 베이스에 옷이 없으면 **덜 덮는 옷을
만들어도 비칠 것이 없다.**

## 레이어 소유권

| 요소 | 소유 | 비고 |
|---|---|---|
| 얼굴·눈·머리카락 | base | 의상이 절대 덮지 않는다 |
| 식물 모티프(꽃·잎·뿔) | base | 감정 원형의 정체성 |
| 피부·손·발·목·다리 | base | 의상 시트에 그리지 않는다 |
| 최소 가림(밴드톱·브리프) | base | 엔벨로프 안. 아동은 바디수트로 대체 |
| 상의·하의·아우터 | outfit | |
| 신발·양말·스타킹 | outfit | 맨발 베이스 위에 얹는다 |
| 장갑·벨트·브로치 | outfit | |

의상 시트에 손이나 목을 그리면 안 된다. 소매 끝과 옷깃은 **비워 두고**, 그
구멍으로 베이스의 손과 목이 보이게 한다.
사람의 팔·손·목을 따라 그린 흰색·크림색 안내용 외곽선도 신체 픽셀로 본다.
1px 선이라도 남기지 않고 해당 위치를 단색 `#FF00FF` 로 비운다.

## 커버리지 엔벨로프

성인 베이스의 최소 가림은 인물 키 기준 **y 0.24 ~ 0.46** 안에만 존재한다.
가슴선 위부터 배꼽 위까지의 밴드톱 + 하이컷 브리프 넓이다. 어깨끈을 만들지
않는 이유는 오프숄더 의상이 덮지 못하기 때문이다.

이 값은 위 실측표보다 위아래로 좁다. 기존 탱크톱(0.17~0.52)이 엔벨로프를
양쪽으로 넘던 것이 바로 디자인이 깨지던 지점이다. 엔벨로프 안에 있으면 지금
만들어 둔 정원 데일리의 짧은 반바지와 오프숄더 원피스도 이너를 전부 덮는다.

색은 **피부보다 한두 단계 어두운 따뜻한 톤**을 쓴다. 봉제선 한 줄이 비쳐도
옷이 아니라 그림자로 읽히게 하려는 것이다. 회색·검정 같은 무채색은 쓰지
않는다. 빌더의 `base-dressed` 검사가 몸통의 무채색 비율로 착의형 시트를
걸러 내기 때문에, 무채색 가림은 그대로 실패한다.

아동(`baby-pot`)은 예외다. **무늬 없는 단색 바디수트가 곧 베이스**다. 목부터
손목·발목까지 덮으며, 노출을 줄이는 방향으로만 벗어난다. 아동 베이스는 어떤
경우에도 맨몸으로 만들지 않는다.

## 자세 고정

의상 시트는 베이스 시트를 **image-to-image로 편집**해서 만든다. 새로 생성하지
않는다. 같은 캔버스에서 출발해야 픽셀이 대응한다.

- 여섯 칸은 `sunny → rainy → ember → moonlit → sparkling → mosaic` 순서
- 각 칸의 팔·다리·허리 각도는 그 칸의 베이스와 **같아야** 한다
- 한 의상 키는 여섯 칸 모두 **같은 옷**이다. 감정별로 색조만 달라진다

v1 초판의 `pretty-pot/outfits/garden-daily`는 이 두 가지를 다 어겼다. 마네킹에
걸린 여섯 벌의 서로 다른 옷을 나열해서, 자세도 안 맞고 한 의상 키도 아니다.
빌더의 `pose-lock` 검사가 이 시트를 걸러 낸다.

## 소스 배치

```text
wardrobe-v1/{캐릭터}/
  base/{idle,diary,grow}-chroma.png      무착의형 베이스
  inner/{idle,diary,grow}-chroma.png     선택. 지금은 비워 둔다
  outfits/{의상키}/{idle,diary,grow}-chroma.png
  legacy-body/                           v1 초판 착의형. 빌드 대상 아님
```

`legacy-body/`는 지우지 않는다. 얼굴·머리·체형을 유지한 채 옷만 벗기는
image-to-image 재생성의 참조 원본이다.

## 재생성 프롬프트

복사해 쓸 수 있는 전체 프롬프트는 [PROMPTS.md](PROMPTS.md)에 있다. 고정해야
하는 항목만 요약하면 다음과 같다. `legacy-body/{state}-chroma.png`를 참조
이미지로 넣는다.

**베이스 (성인)**

1. 참조 시트의 얼굴, 머리 모양, 머리색, 식물 모티프, 체형, 여섯 자세를 그대로 유지
2. 진회색 탱크톱과 반바지를 제거하고 그 자리를 **맨살로** 그린다
3. 가슴선 위 ~ 골반 아래(키의 0.24~0.46)만 **피부보다 한두 단계 어두운 따뜻한
   톤의 밴드톱과 하이컷 브리프**로 덮는다. 어깨끈 없음, 장식 없음, 봉제선
   최소. 회색·검정 금지
4. 맨발, 장신구 없음, 신발 없음
5. 단색 `#FF00FF` 배경, 텍스트·패널선·추가 인물 제외

**베이스 (아동)**

2~3번을 다음으로 바꾼다. 목부터 손목·발목까지 덮는 **무늬 없는 단색
바디수트**를 입힌다. 로고·주머니·프릴을 넣지 않는다.

**의상**

1. 참조로 넣은 **베이스 시트와 같은 캔버스**에서 편집한다
2. 여섯 칸의 자세를 베이스와 정확히 맞춘다
3. 옷·신발·소품만 그린다. **손·목·다리·얼굴은 그리지 않고 비워 둔다**
4. 여섯 칸 모두 같은 옷이며 감정별 색조만 바꾼다
5. 단색 `#FF00FF` 배경

성인형만 매력·노출 표현을 허용하되 노골적 성행위·나체·자해 상징은 제외한다.
`baby-pot`은 모든 분기에서 비성적 마스코트다.

## 빌드

```powershell
python design-system/scripts/build_wardrobe_layers.py `
  --source-root design-system/concepts/wardrobe-v1 `
  --output-root app/assets/wardrobe
```

새 의상을 추가하면 **바디까지 함께 재빌드**한다. 크롭과 스케일을 그 캐릭터의
모든 레이어에서 함께 계산하기 때문에, 의상만 따로 빌드하면 바디와 어긋난다.

출력은 다음과 같다. Flutter의 `assets:` 항목은 하위 디렉터리를 훑지 않으므로
`assets/plants`와 같은 평면 파일명을 쓴다.

```text
app/assets/wardrobe/
  bodies/{캐릭터}-{state}-{form}.webp
  inners/{캐릭터}-{state}-{form}.webp
  outfits/{의상키}-{캐릭터}-{state}-{form}.webp
  previews/{의상키}.webp
```

빌드 결과 요약은 `wardrobe-v1/wardrobe-layers.json`에 남는다. 어떤 캐릭터가
빌드됐고, 어떤 캐릭터가 아직 `base/`를 기다리고, 어떤 프레임이 계약을 어겼는지
들어 있다.

새 레이어 역할을 추가하면 `app/pubspec.yaml`의 `assets:`에 그 디렉터리를 직접
적어야 한다.

## 검사 항목

빌더가 계약 위반을 프레임 단위로 잡고, 하나라도 걸리면 빌드를 실패시킨다.
작업 중에는 `--report-only`로 목록만 볼 수 있다.

| 규칙 | 내용 | 기준 |
|---|---|---|
| `base-dressed` | 베이스에 옷이 남아 있다 | 성인 몸통 무채색 비율 ≤ 35% |
| `envelope` | inner/ 를 만들었는데 엔벨로프를 벗어났다 | y 0.24~0.46 |
| `pose-lock` | 의상 자세가 바디와 다르다 | 의상 픽셀의 55% 이상이 바디 위 |
| `inner-exposed` | 의상이 이너를 못 덮는다 | 노출 25% 이하 |
| `garment-exposed` | 착의형 베이스를 허용한 캐릭터에서 옷이 비친다 | 노출 5% 이하 |
| `source` | 시트를 읽을 수 없다(캔버스 불일치 등) | 그 캐릭터만 건너뛴다 |

기준값은 v1 초판 시트에서 실측해 잡았다. 착의형 몸통은 무채색 비율
0.54~0.67, 맨살은 0.000이 나온다. 자세가 맞는 의상은 픽셀의 58~83%가 바디
위에 있고, 마네킹 시트는 45%까지 떨어진다.

`inner-exposed`가 걸리면 어느 부분이 비는지 자홍색으로 칠한 QA 이미지를
`--qa-root` 아래에 남긴다.

|---|---|---|---|
| baby-pot | 완료 | 완료 | 아동 바디수트. 초판 시트 그대로 |
| handsome-pot | 완료 | 완료 | |
| pretty-pot | 완료 | 완료 | 마네킹 시트 문제 해결 |
| tsundere-pot | 완료 | 완료 | |
| zombie-pot | 완료 | 완료 | |
| gumiho-pot | 완료 | 완료 | |
| ninja-pot | 완료 | 완료 | |
| magical-pot | 완료(착의형 유지) | 완료 | 슈트가 전신을 덮어 재생성 불필요 |
| aloof-pot | 미착수 | 미착수 | |
| student-pot | 미착수 | 미착수 | |

`baby-pot`은 초판 바디가 이미 무늬 없는 단색 바디수트라 그대로 옮겼다.
`magical-pot`은 의상이 전신을 덮어 착의형 바디를 유지한다(`COVERED_BASE_SPECIES`).

`base/`가 비어 있는 캐릭터는 빌드에서 **건너뛰고 목록으로 보고**한다. 시트를
읽을 수 없는 캐릭터도 그 캐릭터만 건너뛰고 나머지는 계속 빌드한다. 착의형
시트를 실수로 `base/`에 넣으면 `base-dressed`가 잡는다.
