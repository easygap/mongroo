## 발견한 문제와 구현

- **진입 경로:** 정원 안의 탐험 탭, 다시 출발 카드, 다시 출발 방식으로 이어졌다. 탐험을 하단 주요 메뉴로 옮겼다. 이전 `/garden?tab=3` 링크는 새 `/explore`로 연결한다. 박물관은 정원의 상단 버튼과 식물 상세에서 열며, 직접 주소로 들어와도 정원으로 돌아갈 수 있다.
- **정보 밀도:** 순찰, 주간 목표, 능력, 연구, 보상표가 하나의 긴 화면에 있었다. 출발 / 순찰 / 기록과 소지품으로 나눴다. 보상표는 필요할 때 펼친다. 탭별 스크롤과 펼침 상태도 독립적으로 저장한다.
- **기록 연결:** 직접 탐험을 완료해도 순찰용 이야기 수치만 보이던 혼동을 고쳤다. 기록 탭 맨 위에서 현재 지역의 완료한 장면과 이야기를 다시 읽는다. 펼친 이야기의 읽음 상태는 서버에 저장하며, 아직 가지 않은 장면의 내용은 보여 주지 않는다.
- **출발:** 일기를 쓰지 않았을 때 가장 큰 버튼이 비활성화되던 화면을 고쳤다. 탐험 시작 하나가 일일 보상이 가능하면 해당 방식, 아니면 자유 탐험으로 출발한다. 보상 조건과 조작 연습은 보조 동작이다.
- **사건 선택:** 네 지역의 비전투 사건 8개, 선택지 24개에 구체적인 결과를 작성했다. 첫 선택은 조사 기록과 발견물, 둘째는 등불 회복, 셋째는 판정 없이 지나가기다. 실패 시 자원 손실, 성공 시 실제 변화, 보상 유무가 서버에서 처리된다.
- **판정:** 서버가 사용하는 1~4 판정으로 정확한 성공 확률을 계산한다. 대원 능력과 일회성 스킬을 반영한다. 방어·비용 감소 스킬도 실패 비용 표시에 반영한다. 기존 저장 탐험에 새 필드가 없으면 이전 규칙으로 동작한다.
- **전투:** 모바일 기술 버튼에 이름, 예상 피해, 집중력 소모·회복을 표시한다. 보통 글자는 3열, 큰 글자는 2열로 바뀐다. 비활성 기술은 잠긴 이유를 읽을 수 있다. 기존 입력 잠금, 재사용 시간, 서버 판정은 유지한다.
- **걷기 조작:** 실제 웹 접근성 모드에서 경로 버튼의 의미 영역이 필드까지 합쳐져, 걷기 입력이 경로 열기로 처리되는 문제를 찾았다. 공통 누름 버튼을 독립된 접근성 영역으로 수정하고 경로 버튼 영역을 검사한다. 잘리던 목표는 누르면 전문을 읽는 수첩 버튼으로 바꿨다.
- **이야기:** 주요 이야기 32개, 단계별 소개 32개, 반복 탐험 이야기 12갈래를 미배달 편지–우물의 반송함–보관고의 난방–관측실의 답장으로 연결했다. 반복 갈래의 시작·중간·세 결말도 서로 다른 행동과 관찰로 작성했다.
- **캐릭터:** 성장 이야기는 창가 자리, 물받이, 잃어버린 단추, 이삿짐 같은 사건으로 바꿨다. 대화 프롬프트와 규칙 기반 응답에서 반복 비유·몸짓 중계·자동 칭찬을 줄였다. 감정 평가 금지와 안전 대화 처리는 유지한다.
- **시각:** teal 계열 잉크와 낮은 채도의 선택색, 작은 모서리, 평평한 패널을 공통 테마에 적용했다. 서고 입구 새 그림을 출발 화면에 연결했다. 걷기 장면의 서고 조명은 길이 읽히도록 밝히고 번짐을 줄였다. 타일 렌더링에서 과한 노란 기를 줄이고, 캐릭터·광원은 구분을 위해 원색을 유지한다. 웹 로딩 화면과 설치 메타데이터도 같은 색으로 맞췄다.

## 생성 이미지

사용 도구: `imagegen` 스킬의 기본 이미지 생성 도구. 생성 1회. 결과를 검토한 뒤 프로젝트에 복사했다.

- 파일: `app/assets/adventure/archive-entrance-v2.png`
- 크기: 1536 × 1024
- 용도: 이끼 기억서고 출발 화면. 걷기 필드나 충돌 지형으로 사용하지 않는다.
- 설정: 식물 표본을 보관하던 온실, 분류대, 편지, 얕은 물, 열린 문. UI나 글자를 그림 안에 생성하지 않았다.

- 마지막 전투 표식의 글자색 조정 후 전투·메뉴 검사 **103개 재검사 통과**.
- Flutter 정적 검사: **No issues found**. 웹 릴리스 빌드 성공.
- 서버 대화·프롬프트·콘텐츠·판정·스테이지·탐험 API 관련 **93개 통과**. 마지막 콘텐츠 문구 수정 후 콘텐츠 검사 **21개**, 귀환 문구 수정 후 보상·패배·자유 탐험 API 검사 **3개 재검사 통과**. 변경 Python 코드 Ruff 검사 통과.
- 새 판정 검사는 선택별 발견물·빛 회복·무보상 결과, 성공률과 실제 판정의 일치, 실패 비용 감소, 자원 상한, 예전 저장 형식 호환, 같은 요청 재전송 시 중복 지급 방지를 확인한다.
- 별도 로컬 테스트 DB와 테스트 계정으로 검증한다. 실제 서비스의 사용자 기록은 사용하지 않는다.
- 브라우저에서 첫 장 전투 완료·귀환, 둘째 장 사건 선택·발견물 표시·새로고침 후 결과 복원, 셋째 장의 드래그·방향키 이동과 전투 기술 사용을 확인했다. 표시 피해 29와 실제 장벽 39→10의 일치, 집중력 소모 후 기술 잠김도 확인했다. 390×844 모바일과 1280×900 데스크톱에서 화면을 검토했다.
- 이전 탐험 주소의 리다이렉트와 정원→박물관→정원 이동을 확인했다. `/museum`을 직접 열어도 정원으로 돌아간다.
- 기록 탭에서 완료한 1·2장만 표시되는 것과 2장의 이야기를 펼쳐 다시 읽는 동작을 브라우저에서도 확인했다.
- 데스크톱 본문 Navigator가 왼쪽 메뉴의 접근성 정보를 가리던 문제도 수정했다. 최종 빌드에서 오늘·기록·정원·탐험·회고가 각각 접근성 버튼으로 노출되는 것을 확인했다. 검증용 화면 크기 설정은 해제하고 탐험 출발 화면을 열어 두었다.

기존 캐릭터 원화, 플랫폼 앱 아이콘, 지역별 전투 시스템은 유지했다. 새로 생성한 그림은 서고 입구 1종이다. 규칙 기반 대화의 자동 검사는 수행하며, 운영 LLM의 실제 응답 품질은 해당 모델을 연결한 별도 평가가 필요하다. 이번 작업은 로컬 코드와 실행 결과이며 서비스 배포는 포함하지 않는다.
