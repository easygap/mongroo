경로, 레벨별 능력치, 성장 단계 진화, 상점 등급과 성능의 관계, 라이브 밸런스 운영을
하나의 계약으로 고정한다. 구현 중 세부 판단이 필요하면 이 문서를 우선하고, 여기서
정하지 않은 것은 `interactive_adventure_design.md`의 불변식을 그대로 따른다.

v1.3은 단순 아이디어 문서가 아니다. 레벨 경계, 계산 순서, 품종별 스킬, 감정 스킬
6종, 스킬북 36종, 몬스터 상성, 획득 경로, 데이터 모델, API, 에셋 수량,
패치·환불·롤백, 테스트 합격선을
모두 닫은 **구현 계약**이다. 표에 없는 수치나 예외를 구현 편의로 추가하지 않는다.

## 문서 적용 전제

몽그루의 본편은 여전히 마음 일기다. 이 문서가 스킬과 수치를 상세히 다루는 이유는
캐릭터를 강하게 만들기 위해서가 아니라, **오래 기록한 시간이 눈에 보이는 형태로
돌아오게 하기 위해서**다. 다음 다섯 줄은 이 문서의 모든 수치보다 우선한다.

1. 레벨·진화·스킬북은 하루 XP 50과 일기 우선 보상 순서를 절대 바꾸지 않는다.
2. 무료 스타터 캐릭터 한 명과 정원 길잡이만으로 모든 필수 콘텐츠를 완주할 수 있다.
3. 씨앗은 현금으로 살 수 없다. 비싼 캐릭터는 과금이 아니라 **기록한 날의 수**로 산다.
4. 강해진다는 감각은 숫자만 키우지 않고 **선택지·연출·운용 숙련이 함께 늘어나는 것**으로 만든다.
5. 확률형 획득, 강화 실패, 재화 소각, 시즌 초기화는 어떤 형태로도 만들지 않는다.

## 1. 기존 불변식과 이 문서가 바꾸는 것

이 확장은 기존 문서의 규칙 세 줄을 명시적으로 개정한다. 개정하지 않은 규칙은 전부
그대로 유효하며, 개정한 자리에는 반드시 대체 가드레일을 둔다.

| 기존 규칙 | 원문 위치 | 이 문서의 개정 | 대체 가드레일 |
|---|---|---|---|
| 품종은 기본 능력치를 추가하지 않고 고유 스킬과 연출만 다르게 한다 | 탐험 설계서 3.3 | 유지. 등급 차등은 **탐험 4능력치가 아니라 수호전 위력 계수**에만 적용 | 탐험 `effective_stat` 계산식은 등급을 읽지 않는다. CI가 등급 인자 사용을 금지 |
| 능력치는 `3 + stage + 성장형 보정` | 탐험 설계서 3.3 | `+ 단계 내 성숙 보정(0 또는 1)` 추가 | 지역 상한 7~10과 필수 DC 13은 변하지 않는다. 보정 후에도 상한이 그대로 적용된다 |
| 노드로 고유·성장형 스킬 충전 횟수를 추가하지 않는다 | 스킬트리 카탈로그 7.3.1 | 트리 노드는 계속 금지. **진화 T3만** 쉼터 회복 대상에 고유 스킬을 포함 | run 전체에서 고유 스킬 회복은 1회. 성장형 스킬 회복 1회와 합쳐 run당 총 2회를 넘지 않는다 |
| 대원 HP는 3 | 수동 지휘 계약 4 | 레벨에 따라 3~6 | 적 위력은 성장으로 오르지 않는다. HP 상승은 전멸 위험만 낮추고 클리어 시간은 장벽 스케일이 담당 |
| 화면 버튼은 품종 고유 1 + 성장형 1 | 탐험 설계서 0·7 | 고유 I에 전투 payload를 추가하고 고유 II·선택 B1·B2와 함께 4스킬 슬롯으로 고정. B에는 감정 스킬 또는 기록서 장착 | 전투는 기본·4스킬·지키기 6아이콘 벨트, 탐험은 유효한 문맥 행동만 노출. 전문은 길게 누르기 |
| 스킬트리 노드는 고유 스킬의 대체 사용법 | 스킬트리 카탈로그 1 | 유지. 진화·기록서와 계산 순서만 추가 | v1의 모든 `signature_retarget`은 완전 대체이며 진화 효과와 임의 합산하지 않는다 |

다음 규칙은 이 문서에서도 **절대 바꾸지 않는다**.

- 여섯 성장형의 능력 예산은 같다. 특정 감정이 유리해지는 경로를 만들지 않는다.
- 일일 XP 50, 일기 XP 40·씨앗 15가 단일 활동 최대치라는 순서를 유지한다.
- 스킬·스킬북·레벨·진화는 XP, 씨앗, 수집품 수량, 가치 예산을 1도 바꾸지 않는다.
- 특정 품종·등급·보유 수를 입장 조건이나 주간 제한으로 만들지 않는다.
- 캐릭터는 죽거나 잃어버리거나 퇴화하지 않는다. 스킬북도 파괴·소모되지 않는다.
- 확률형 상자, 강화 성공률, 행동력 충전, 입장권 판매를 만들지 않는다.

## 2. 네 슬롯 구조

### 2.1 슬롯 정의

| 슬롯 | 이름 | 공간 | 해금 | 교체 | 개수 |
|---|---|---|---|---|---:|
| `S1` | 품종 고유 · 길/기본기 | 탐험 지도·사건 + 전투 | stage 2 | 불가 | 1 |
| `S2` | 품종 고유 · 수호 | 수호전 | stage 2 | 불가 | 1 |
| `B1` | 선택 스킬 I | 감정 스킬 또는 기록서의 공간 | stage 3 / Lv9 | 자유 | 1 |
| `B2` | 선택 스킬 II | 감정 스킬 또는 기록서의 공간 | stage 5 / Lv23 | 자유 | 1 |

성장형 스킬 6종은 탐험에서는 슬롯을 차지하지 않는 캐릭터 고유 문맥 행동이다. 전투에서는
stage 3부터 `emotion.primary`, stage 4부터 공개된 보조결이 있으면 `emotion.secondary`로
B1/B2에 **선택 장착**할 수 있다. 이 포인터는 활성 캐릭터의 현재 안정 주결·보조결,
수확 캐릭터의 고정된 감정 profile을 실제 family code로 해석한다.
진행 중 run은 시작 snapshot을 유지하므로 일기 분석이 끝나도 전투 도중 아이콘·상성이
바뀌지 않는다.

### 2.2 네 슬롯은 보이되 설명 패널은 늘리지 않는다

네 슬롯은 캐릭터 정체성과 수집·교체의 핵심이므로 준비 화면과 전투에서 숨기지 않는다.
대신 큰 카드·팝업 목록·상시 전문을 없애 전장 면적을 지킨다.

| 화면 | 고정 조작 | 표현 규칙 |
|---|---|---|
| 탐험 지도·사건 | 고유 I, 성장형, 현재 유효한 기록서 | 현장 오브젝트 옆 문맥 아이콘만 나타나며 유효하지 않은 전투 스킬은 숨김 |
| 전투 | 기본 공격 / `S1` / `S2` / `B1` / `B2` / 마음 지키기 | 행동 대원 아래 6아이콘 고정 순서. 고유·감정·기록서는 각각 전용 도색 그림 사용 |
| 캐릭터 상세 | `S1·S2` 고정 + `B1·B2` 교체 | 2×2 슬롯 보드. 위 고유 2개, 아래 선택 2개 |

선택 스킬을 장착하지 않은 슬롯은 빈 잎눈 윤곽과 `장착 안 함`으로 남고 다른 스킬을
복제해 채우지 않는다. 감정 스킬과 `activation_mode=command` 책은 짧게 탭해 선택·실행한다.
`opening|trigger` 책은 같은 슬롯에 `자동` glyph와 발동/대기 상태를 표시하되 탭으로
가짜 명령을 만들지 않는다. 평상시에는 이름·한 줄 설명·전문을 아이콘 주변에 표시하지
않고, 모든 아이콘을 길게 누를 때만 전투를 일시 정지한 peek sheet에서 읽는다. 한 확정
행동에 같은 `stack_group`을 두 개 겹칠 수 없다는
규칙은 그대로 적용한다.

### 2.3 잠금 표시 규칙

잠긴 슬롯은 숨기지 않고 이유를 문장으로 보여 준다. `줄기가 되면 선택 스킬 한 칸이
열려요`, `만개하면 두 번째 선택 스킬을 챙길 수 있어요`처럼 다음 목표를 알려
주되 남은 exp를 진행 바로 압박하지 않는다. 잠금 사유 문구는 서버가 내려 준
`lock_reason_key`를 앱·스크린리더가 같은 문구로 읽는다.

### 2.4 스킬트리·진화·선택 스킬 계산 순서

같은 행동에 여러 시스템이 관여하므로 서버는 아래 순서를 바꾸지 않는다.

```text
1. 요청한 행동 슬롯과 activation hook을 정규화
2. 기본/지키기는 공통 payload, S1/S2는 영구 family·tier payload,
   B1/B2는 snapshot에 resolve된 감정/기록서 payload 중 정확히 하나를 선택
3. 같은 action space의 스킬트리 node가 있으면 명시된 대체 효과로 교체
4. opening/trigger 기록서는 선언된 hook에서만 자동 적용하고 별도 행동처럼 합성하지 않음
5. 기본 공격과 고유 I 전투 payload는 등급 계수 50%, 고유 II는 100%,
   감정/기록서 선택 스킬의 정액값은 등급 계수 0% 적용
6. 여섯 성장결 상성·T3 조건·적 상태 적용
7. stack group·전역 상한 검증
8. 정수 반올림 후 결과와 계산 근거를 action snapshot에 저장
```

- v1 스킬트리의 `signature_retarget`은 기본 효과를 **완전히 대체**한다.
  `inherits_tier_target=false`가 기본값이며, T2 대상 확장이나 T3 부가 효과를 자동으로
  더하지 않는다. 상속이 필요한 미래 node는 콘텐츠에 명시하고 별도 조합 테스트를 갖는다.
- 현재 90노드는 탐험 고유 I에만 적용한다. 고유 I 전투 payload는 6.2 표를 그대로 쓰고
  탐험 `signature_retarget`을 자동 합성하지 않는다. 미래 combat node는 별도
  `space=combat`과 조합 fixture 없이는 전투 요청에서 선택할 수 없다.
- 한 전투 명령은 `기본|지키기|S1|S2|B1|B2` 중 하나만 고른다. S1에 B1을 겹쳐 보내거나
  command 책을 다른 스킬의 보정처럼 붙일 수 없다. 자동 opening/trigger가 같은
  `stack_group`에서 충돌하면 출발 전에 해결하고 강한 쪽을 임의 선택하지 않는다.
- 감정 스킬과 스킬북의 정액 피해·회복·방어에는 캐릭터 등급 계수를 곱하지 않는다.
  비싼 캐릭터가 같은 선택 스킬까지 더 강하게 쓰는 이중 증폭을 막는다.
- 서버 응답은 최종 수치뿐 아니라 `slot/source → base|tier|selected payload → tree/auto hook → rarity bp → affinity → condition → cap`의
  계산 줄을 내려 주며 앱은 이를 그대로 표시한다.

### 2.5 장착 프리셋과 파티 중복

- 캐릭터마다 `탐색`, `수호`, `개인` 세 프리셋을 저장할 수 있고 파티 준비에서
  한 번에 바꾼다. 프리셋 변경은 run 밖에서 무료·무제한이다.
- 기록서는 계정 라이선스이므로 같은 책을 여러 캐릭터의 프리셋에 저장할 수 있다.
  대신 **실제 출발 파티 snapshot에는 같은 책 code가 한 번만** 들어간다. 캐릭터마다
  파생되는 `emotion.current`는 같은 성장결이어도 중복으로 보지 않는다.
- 중복이 생기면 최근 캐릭터의 책을 임의로 빼지 않는다. 세 캐릭터와 충돌 슬롯을
  모두 표시하고 사용자가 한 번 선택해야 출발할 수 있다.
- 진행 중 run의 프리셋은 바뀌지 않는다. `마음결 대백과`처럼 전투 중 교체를 명시한
  기록서만 해당 run snapshot 안에서 예외를 만든다.

## 3. 레벨 시스템

### 3.1 활성 레벨은 기존 exp의 눈금이다

탐험 XP, 전투 XP, 숙련 XP를 새로 만들지 않는다. 활성 캐릭터 레벨은 이미 존재하는
식물 exp에서 파생하는 읽기 전용 값이며 `level_from_exp()`를 `stage_from_exp()` 옆의
단일 도메인 함수로 둔다. 수확 뒤에는 exp를 더하지 않고 3.6의 회향 단계만 합산한다.

```text
base_level = level_from_exp(plant.exp)
effective_level =
  base_level                                      if status == active
  min(30, base_level + reflection_levels)         if status == harvested
```

`stage`와 감정 성장 외형은 항상 `plant.exp`만 읽는다. 회향으로 전투 레벨이 올라도
수확한 외형·성격·감정 분기·박물관 기록은 바뀌지 않는다. 결국 활성 성장의 가장 빠른
원본과 수확 뒤 느린 성장의 원본이 모두 마음 일기라는 규칙이 유지된다.

레벨을 도입하는 이유는 세 가지다. 첫째, stage 5단계만으로는 3주 넘게 기록해도
아무 변화가 없는 구간이 길다. 둘째, 만개(exp 450) 이후 수확 전까지 성장 피드백이
완전히 사라진다. 셋째, 진화·슬롯 해금 시점을 stage보다 촘촘하게 잡아야 "다음에 뭐가
열리지"라는 기대가 끊기지 않는다.

### 3.3 단계 내 성숙 보정

```text
raw_stat = 3 + stage + 성장형 보정 + maturity(level)
maturity(level) = 1 if level >= 해당 stage 구간의 하위 절반을 지났을 때 else 0
effective_stat = min(synced_stat, 지역 능력치별 상한)
```

- `maturity`는 0 또는 1만 가지며 한 stage 안에서 한 번만 오른다.
- 지역 상한(기억서고 7 ~ 관측실 10)은 그대로 적용된다. 보정이 붙어도 상한을 넘지
  않으므로 필수 DC 13 대비 최대 유효 능력치 10이라는 계약은 변하지 않는다.
- 실제 효과는 "상한에 조금 더 일찍 도달한다"이며 상한 자체가 오르지 않는다.
- UI는 `원래 8 · 성숙 +1 → 9`, `지역 상한 9`처럼 계산 근거를 계속 전부 공개한다.

### 3.4 모든 레벨에서 보이는 변화

레벨이 올랐는데 아무 숫자도 달라지지 않는 구간을 만들지 않는다. 다만 정수 위력에
매번 +1을 넣으면 인플레이션이 커지므로 서버는 5장의 등급 계수를 basis point 정수로
계산하고 최종 행동에서 한 번만 반올림한다.

```text
rarity_scale_bp = round(
  (base(rarity) + slope(rarity) * (level - 1) / 29) * 10_000
)
basic_rarity_bp = 10_000 + round((rarity_scale_bp - 10_000) * 0.5)
```

- 기본 공격과 고유 I 전투 payload는 `basic_rarity_bp`, 고유 II는
  `rarity_scale_bp`를 사용한다.
- 탐험 네 능력치는 표의 성숙 레벨에서만 +1, HP는 Lv10·19·27, 시작 집중력은
  파티 평균 Lv18에서 오른다. 이 값은 사용자가 기억할 수 있는 큰 이정표다.
- 레벨 화면은 `이번 레벨: 고유 위력 계수 1.206 → 1.218`처럼 실제 변화를 보여 주고,
  전투 화면은 반올림이 끝난 예상 피해를 표시한다. 소수점만 올랐는데 정수 피해가
  그대로인 레벨도 다음 반올림 경계 진행도를 함께 보여 준다.
- 클라이언트는 float로 다시 계산하지 않는다. 서버가 내려 준 bp와 예상 정수를 그린다.

### 3.5 탐험 판정에서 레벨을 더 크게 쓰지 않는 이유

레벨 30단계를 탐험 판정에 그대로 얹으면 상한 7~10, DC 8~13이라는 좁은 창에 즉시
붙어 버린다. 그러면 상한을 올릴 수밖에 없고, 상한을 올리면 "새 지역이 이전 캐릭터를
숫자로 폐기하지 않는다"는 핵심 약속이 무너진다. 따라서 레벨의 수치 성장은 상한이
없는 공간, 즉 수호전으로 보낸다. 탐험에서 레벨이 만드는 변화는 숫자가 아니라
**진화 tier와 기록서 슬롯이 여는 새로운 행동**이다.

### 3.6 수확 캐릭터와 회향

- 수확해도 `plant.exp`를 보존하므로 `base_level`이 그대로 남는다. 별도
  `final_level` 중복 컬럼을 만들지 않는다.
- **주간 마음 일기 3일 목표**를 채울 때 계정당 회향 기회 1회를 얻는다. 탐험·상점·
  광고·현금·다른 재화 변환으로는 얻을 수 없다.
- 회향 1회는 선택한 수확 캐릭터의 `reflection_levels`를 1 올린다. 합산 상한은
  Lv30이며, +3 같은 영구 손해 상한을 두지 않는다. 일찍 수확하면 느리지만 끝까지
  완성할 수 있다.
- 사용하지 않은 기회는 `weekly_reflection_entitlements`에 만료 없이 남는다. 거래·
  구매·분해할 수 없고, 수량을 상점 잔액처럼 강조하지 않는다.
- 회향은 `stage`, `plant.exp`, `final_form`, `growth_persona`, 감정 프로필,
  박물관 생애 스냅샷을 바꾸지 않는다. 오직 전투 레벨·HP·tier 해금만 다시 계산한다.
- 이미 Lv30인 캐릭터에게 적용하면 409로 거절하고 기회는 소비하지 않는다.

## 4. 진화

### 4.1 진화는 새 캐릭터가 아니라 같은 스킬의 다음 형태다

수집형 RPG 진화의 재미는 "같이 지낸 존재가 한 단계 달라졌다"는 감각이다. 몽그루에서
외형 진화는 이미 stage 2~5 성장 원화가 담당하고 있다. 이 문서는 그 위에
**스킬의 진화**를 얹는다.
스킬 이름·tier 표식과 아이콘이 바뀌고, 연출 구성은 한 층 깊어지며, 효과의 적용
범위가 넓어진다.
버튼 개수와 조작 방법은 바뀌지 않아서 다시 배울 필요가 없다.

외부 게임의 캐릭터 실루엣, 기술명, 속성표, 진화 UI, 사운드 문법을 복제하지 않는다.
참고하는 것은 `레벨업의 작은 변화 + 단계 진화의 큰 변화 + 새 행동 학습`이라는
보편적 리듬뿐이며, 몽그루의 감정 성장·식물 모티프·마음결 기록서 언어로 다시 만든다.

### 4.2 진화 문법

모든 품종이 같은 문법을 쓴다. 품종마다 다른 것은 문장이지 규칙이 아니다.

| tier | 조건 | 고유 I이 얻는 것 | 고유 II가 얻는 것 |
|---|---|---|---|
| T1 | stage 2 (Lv 3) | 기존 탐험 효과 + 6.2의 1집중 저비용 전투 기본기 | 현재 구현된 위력·효과 |
| T2 | stage 4 (Lv 16) | 탐험 **대상 확장** + 전투 raw P를 올리지 않는 전술 효과 1개 | **부가 효과 1개** — 6.3의 단일 effect budget 안에서 선택 |
| T3 | stage 5 이후 Lv 25 | 탐험 쉼터 회복 + 전투에서 관찰 가능한 조건부 전술 강화 | **조건부 상위** — 항상 등급 bp를 적용하고 관찰 가능한 품종 조건으로 저점·고점을 나눔 |

- T2 고유 I은 raw damage를 올리지 않고 대상·방어·회복·정보 중 하나만 넓힌다. 고유
  II도 단일 effect budget을 넘지 않는다.
- T3의 탐험 회복은 run 전체 1회이며, 기존 성장형 스킬 회복 1회와 합쳐 **run당 총
  2회**를 넘지 않는다. 쉼터를 오가며 무한 회복할 수 없다는 규칙은 그대로다.
- 두 고유 스킬의 T3 조건은 품종 정체성과 직결된 관찰 가능한 상태여야 한다. 숨은
  확률은 없다.
- 진화 tier는 되돌리거나 골라 쓰지 않는다. T3는 조건을 놓친 한 행동의 저점이 있을 수
  있지만, 같은 레벨의 상태 가중 기대 기여가 T2보다 낮아지면 validator가 실패한다.

### 4.3 진화 순간의 연출 계약

- 진화는 탐험 중에 일어나지 않는다. 일기를 써서 레벨이 오른 뒤 **홈 화면**에서 한
  번만 재생한다. 탐험 중 스냅샷은 시작 당시 tier를 유지한다.
- 연출은 2.4초를 넘지 않고, 건너뛸 수 있으며, `disableAnimations`에서는 정지 화면과
  변경 요약 문장으로 대체한다.
- 문구는 성능을 앞세우지 않는다. `새싹 응원이 잎우산으로 자랐어요. 이제 친구까지
  감쌀 수 있어요.`처럼 무엇이 달라졌는지를 먼저 말한다.
- 진화 알림은 하루 최대 2회만 띄우고, 나머지는 캐릭터 상세 화면의 배지로 남긴다.

## 5. 등급과 성능의 관계

### 5.1 문제 정의

상점의 비싼 캐릭터가 값어치를 해야 한다는 요구와, 무료 캐릭터로도 모든 콘텐츠를
완주할 수 있어야 한다는 약속은 정면으로 부딪힌다. 이 문서는 **등급이 후반 성장
기울기·조건을 맞췄을 때의 고점·전용 표현량을 산다**는 원칙으로 둘을 동시에 만족시킨다.

씨앗은 현금으로 살 수 없으므로 이 구조는 과금 격차가 아니라 **기록한 날 수의 격차**다.
180씨앗짜리 설화를 사려면 대략 12일치 일기가 필요하다. 그 12일이 헛되지 않았다는
감각을 주되, 설화가 없어서 필수 길을 못 가는 상황은 0건이어야 한다. 가격·등급의 단일
원본은 `plant_species.unlock_price`와 `plant_species.rarity`이며 문서에만 다른 값을
적어 두지 않는다.

### 5.2 등급이 사는 것과 사지 않는 것

| 등급이 사는 것 | 등급이 사지 않는 것 |

| 진화 연출 길이 안에서의 표현 밀도 | 파티 인원, 지역 해금, 일일 보상 자격 |

비싼 캐릭터는 **잘 키우고 알맞게 지휘했을 때 실제로 더 강하다.** 다만 낮은 등급은
조건이 단순하고 저점이 높아 자동 지휘·첫 도전·불리한 조합에서 더 안정적이다. 따라서
가격표는 일방적인 상위 호환이 아니라 `안정성 ↔ 숙련 고점`의 차이를 구매 전에
그대로 보여 준다.

### 5.3 위력 계수 공식

수호전에서만 사용한다. 탐험 판정 계산식은 이 값을 읽지 않는다.

```text
scale = base(rarity) + slope(rarity) * (level - 1) / 29
rarity_scale_bp = round_half_up(scale * 10_000)
basic_rarity_bp = 10_000 + round_half_up((rarity_scale_bp - 10_000) * 0.5)

signature_1_power = round_half_up(raw_signature_1_power * basic_rarity_bp / 10_000)
signature_2_power = round_half_up(raw_signature_2_power * rarity_scale_bp / 10_000)
basic_power = round_half_up(raw_basic_power * basic_rarity_bp / 10_000)
```

| 등급 | 대표 캐릭터 | 가격 | `base` (Lv1) | `slope` | Lv30 계수 | 무료 등급 대비 |
|---:|---|---:|---:|---:|---:|---|
| 1 | 뽀또 | 0 | 1.00 | 0.20 | 1.20 | 기준 |
| 2 | 로제온, 블루미 | 50 | 0.98 | 0.25 | 1.23 | Lv1 −2% / Lv30 +2.5% |
| 3 | 가시로, 시들잎 | 80·90 | 0.96 | 0.30 | 1.26 | Lv1 −4% / Lv30 +5% |
| 4 | 여우비, 그림싹, 하루 | 120·120·130 | 0.94 | 0.35 | 1.29 | Lv1 −6% / Lv30 +7.5% |
| 5 | 별솔, 설화 | 150·180 | 0.92 | 0.40 | 1.32 | Lv1 −8% / Lv30 +10% |

| 레벨 | 등급 1 | 등급 2 | 등급 3 | 등급 4 | 등급 5 |
|---:|---:|---:|---:|---:|---:|

- 다섯 등급은 **레벨 12와 13 사이**에서 교차하고 UI의 소수 셋째 자리 표시에서는
  Lv13에 거의 같은 값으로 보인다.
  즉 **신규 사용자가 처음 2주 동안 만나는 구간에서는 무료 캐릭터가 오히려 강하다.**
  비싼 캐릭터는 오래 키운 사람에게만 앞선다.
- Lv30의 기본 공격과 고유 I은 계수를 절반만 반영해 등급 1이 1.10, 등급 5가
  1.16이다. 고유 II는 1.20과 1.32이므로 기본기 격차는 약 5.5%, 결정기 격차는
  10%다.
- 캐릭터 고유 `power`(11~20)는 현재 값을 시작점으로 유지하되 5.5의 실제 기여
  시뮬레이션을 통과해야 한다. 피해량이 낮아도 회복·방어·집중력까지 합쳐 강하면
  추가 상향하지 않는다.

### 5.4 조건 구조

고유 II T3는 품종별 조건을 가진다. 조건은 등급이 높을수록 까다롭고 보상이 크다.
고유 I T3도 6.2의 관찰 조건을 쓰지만 별도 배수를 곱하지 않고 표에 적힌 단일 전술
효과만 연다. 두 스킬을 한꺼번에 계산한 결과가 5.6의 상한을 넘을 수 없다.

| 등급 | 조건 충족 배수 | 미충족 배수 | 설계 기대 발동률 | 기대값 |
|---:|---:|---:|---:|---:|
| 1 | ×1.00 | ×1.00 | 조건 없음 | 1.000 |
| 2 | ×1.04 | ×0.96 | 0.70 | 1.016 |
| 3 | ×1.07 | ×0.93 | 0.62 | 1.017 |
| 4 | ×1.10 | ×0.90 | 0.56 | 1.012 |
| 5 | ×1.14 | ×0.86 | 0.50 | 1.000 |

조건 배수 자체의 기대값은 1.00~1.02 안에 들어온다. 여기에 5.3의 후반 등급 계수가
붙으므로 **같은 레벨의 평균은 비싼 캐릭터가 최대 10% 앞서고, 조건을 직접 맞추면
순간 고점은 약 25% 앞선다.** 조건을 놓치면 낮은 등급보다 약할 수 있다.

이 표의 기대 발동률은 초행·숙련·자동 지휘를 분리한 실제 로그로 검증하며 ±0.08을
벗어나면 조건 문장·적 의도 분포·자동 지휘 순서를 먼저 고친다. 자동 지휘를 일부러
멍청하게 만들지 않으며, 화면에 드러난 조건은 가능한 행동 순서 안에서 정상적으로
활용한다.

### 5.5 실제 전투 기여 예산

`rarity_scale_bp × 조건 배수`만 비교하면 기본 `power`와 회복·방어·집중력 효과를 놓친다.
따라서 고유 I·II, 감정 스킬, 기록서까지 아래 표준 상태 묶음에서 **실제 전투 결과**로 다시
비교한다.

```text
6 행동 속성 × 3 상성 관계(약점/중립/내성)
× 4 적 의도 profile(front/lowest/all-light 1~2/all-heavy 3)
× 4 아군 HP 상태(full/mixed/low/one-down)
× 3 집중력 상태(0~1/2~3/4~5)
× 3 장벽 구간(100~61/60~21/20~0)
= 2,592개 환경 상태
× 2 고유 I charge 상태(사용 가능/소진)
= 5,184개 명령 상태
```

- 각 상태에서 기본 공격, 고유 I, 고유 II, 장착한 감정 스킬·기록서, 방어를 각각 선택한 뒤
  남은 장벽, 아군 HP,
  다음 라운드 집중력, 예상 종료 라운드, 승패를 기록한다.
- 고유 I 소진 상태에서는 S1 선택을 불법으로 처리하고 다른 행동의 최적 정책을 다시
  계산한다. 사용 가능 상태의 고점만 평균에 넣어 일회성 기본기를 과대평가하지 않는다.
- 피해 1과 회복 1을 임의 점수로 환산하지 않는다. 실제 6라운드 시뮬레이터에서
  `승률 변화 + 평균 라운드 변화 + 잔여 HP`를 함께 본다.
- 같은 등급·레벨에서 품종별 최적 정책 승률은 중앙값 ±5%p, 평균 라운드는 중앙값
  ±0.4 안에 있어야 한다. 벗어나면 계수보다 기본 `power`와 effect budget을 먼저 고친다.
- 새 품종·감정 스킬·몬스터는 출시 전 2,592환경/5,184명령 상태 전수 계산과 10,000 seed
  파티 시뮬레이션을 모두 통과한다.

### 5.6 절대 상한

어떤 레벨·등급·진화·스킬북·의상 조합에서도 다음을 넘지 않는다. 넘으면 CI 실패다.

| 상한 | 값 | 검증 방법 |
|---|---:|---|
| 같은 레벨 계수 상한 — `rarity_scale_bp × 조건 배수` 최고/최저 비 | 1.35 | 등급 5 Lv30 조건 충족 1.505 ÷ 미충족 1.135 = 1.326 |
| 같은 레벨 등급별 **기대** 위력 차 | 10% | 조건 발동률 가중 평균 |
| Lv25~30 등급 5 최적 운용 ÷ 등급 1 안정 운용의 실제 기여 | 평균 1.25·P95 1.35 이하 | 2,592환경/5,184명령 상태 + 파티 시뮬레이션 |
| 같은 등급·레벨 품종별 승률·라운드 편차 | ±5%p·±0.4 | 기본 power와 유틸리티까지 포함 |
| 기록서 포함 파티 총 위력 — 3인 최대 조합 ÷ 미장착 동일 파티 | 1.60 | 기록서는 계수가 아니라 정액 효과이므로 별도로 잰다 |
| 탐험 유효 능력치 | 10 | 기존 계약 유지 |
| 필수 판정 DC | 13 | 기존 계약 유지 |
| 등급 1 Lv 3 캐릭터 1명 + 길잡이 2명의 전 지역 필수 경로 완주율 | 100% | 10,000 seed 시뮬레이션 |
| 등급 1 Lv 8 + 길잡이의 최신 지역 `gentle` 수호전 승률 | 90% 이상 | 10,000 seed 시뮬레이션 |
| 등급별 일일 씨앗·XP 획득 차이 | 0 | 원장 집계 |

## 6. 품종별 고유 스킬 2종 전체 카탈로그

### 6.1 표기 규칙

- 스킬 code는 tier와 분리한 **영구 family code**다. 진화해도 code를 바꾸지 않고
  `tier: 1|2|3`과 표시 이름만 바꾼다. 저장·분석·환불·snapshot이 이름 변경에
  깨지지 않게 하기 위한 규칙이다.
- 고유 I은 현재 code인 `baby-pot.sprout-cheer`, `handsome-pot.composed-command`
  같은 값을 그대로 쓴다. 고유 II도 현재 `sprout_cheer`, `warm_command` 같은 값을
  유지한다. 보기 좋은 새 code를 만들기 위해 운영 중인 값을 폐기하지 않는다.
- 고유 I 탐험 T1과 고유 II 전투 T1은 현재 구현(`server/app/content/expeditions/skills.py`,
  `combat.py`)을 승계한다. 고유 I의 전투 payload는 v1.3에서 6.2 표가 단일 원본이다.
- 뽀또의 탐험 고유와 전투 고유가 지금 둘 다 `새싹 응원`이다. 전투 쪽을
  **`포근한 싸개잎`**으로 표시만 개명하고 `sprout_cheer` code는 유지한다.
- tier별 표시 이름 60종과 진화 안내 문구 40종은 6.4·6.5가 단일 원본이다. 표시
  이름은 localization key로만 배포하며 code·snapshot·분석 이벤트에 절대 넣지 않는다.
- 구버전 별칭이 추가로 생기면 `skill_code_aliases`의 `old → canonical` 닫힌 맵으로
  정규화한다. 별칭은 요청 호환에만 쓰고 새 응답·새 snapshot에는 canonical만 기록한다.

| 하루 `student-pot` | `student-pot.field-organize` | 현장 정리 | 성장형 스킬 1회 회복 또는 길빛 2 회복 | 회복 대상을 다른 대원으로 지정 가능 | 공통 T3 회복 규칙 적용 |

공통 T3 회복은 자동 충전이 아니다. T3 고유 I을 쓴 뒤 처음 도착한 쉼터에
`사용한 고유 I 하나 회복` 선택이 생기고, 사용자가 대원을 고르면 run 전체에서
한 번만 회복한다. 고유 I 회복 1회와 성장형 스킬 회복 1회는 서로 다른 예산이지만
합쳐 run당 2회를 넘지 않는다. 쉼터를 지나쳤다고 보상·씨앗으로 대신 지급하지 않는다.

탐험 T2는 전부 "같은 크기, 넓은 대상"이다. 탐험 판정 수치가 오르는 항목이 하나도
없는지 콘텐츠 validator가 확인한다.

고유 I은 전투에서 캐릭터다운 저비용 기본기가 된다. 기본 공격을 없애는 상위 호환이
아니라 **전투당 1회** 쓸 수 있는 전술 카드이며, 탐험 charge와 전투 charge는 snapshot
안에서 별도로 기록한다. `P`는 성장결 상성·레벨·등급을 적용하기 전 raw 장벽 피해, 슬래시 뒤는
집중력 비용이다. 등급 계수는 50%만 적용한다.

- `battle_charge=1`은 전투 전체에서 공유하며 웨이브가 바뀌어도 회복하지 않는다. 쉼터

  숨은 확률로 바꾸거나, T3에서 P 자체를 별도 배수로 올리지 않는다.
- 고유 I·II를 같은 대원이 한 라운드에 연속 사용할 수는 없다. 대원당 라운드 행동은
  여전히 하나이며, 공유 집중력과 명령 순서가 선택 비용이다.

### 6.3 고유 II — 수호와 전투 결정기

집중력 1, 피해 최대 +4, 정보 1회, 또는 같은 기대 예산의 조건 범위 확장 중 하나만
더한다. 두 효과를 붙였다면 validator가 실패한다.

### 6.4 tier 표시 이름 카탈로그

진화가 "같은 스킬의 다음 형태"라는 4.1의 약속은 이름에서 먼저 보여야 한다. 60종
표시 이름은 이 표가 단일 원본이며, 10.2의 고유 스킬 아이콘 60개와 1:1로 대응한다.

이름 규칙은 다음 다섯 줄이다.

1. 이름은 표시 전용이다. family code·별칭·저장·분석 이벤트 어디에도 쓰지 않는다.
2. T1 이름은 현재 구현 표시를 그대로 승계한다. 운영 중 이름을 소급 개명하지 않는다.
3. `강화`·`개(改)`·`+`·로마숫자·`EX`·`진(眞)` 같은 성능 접미사를 금지한다. T2·T3는
   접미사가 아니라 **품종 모티프(10.3)가 자란 새 명사구**여야 한다.
4. T2 이름은 넓어진 대상을, T3 이름은 품종 서사의 완성형을 가리킨다. 이름이 실제
   효과와 다른 것을 약속하면 안 된다. 예: `잎우산`은 파티원을 덮는 T2 효과 그 자체다.
5. 60종 이름은 서로 중복되지 않고, 기록서 36종·스킬트리 90노드·의상·방 테마 이름과도
   문자열이 겹치지 않는다. 출시 전 외부 게임 기술명과의 일치 여부를 검색으로 확인한다.

### 6.6 역할 체계 — 파티에서 맡는 자리

스킬 카탈로그(6.2·6.3)는 개별 효과를 정의하지만, 사용자가 파티를 짤 때 "이
캐릭터는 무엇을 맡는 캐릭터인가"를 한 단어로 읽을 언어가 없었다. 역할은 그
언어다. 세계관에서는 관리인들이 도와주러 온 친구를 부르는 **여섯 부름말**이며,
서사적 유래는 `docs/expedition_story_design.md` 5장이 정의한다.

역할의 네 원칙.

1. 역할은 **분류 라벨이지 수치 태그가 아니다.** 서버의 판정·계수·보상 계산은
   role 값을 읽지 않는다. 역할의 단일 원본은 콘텐츠 fixture
   (`character_skill_growth_v1.json`의 `role_primary`·`role_secondary`)이며 DB
   컬럼이나 판정 코드에 넣지 않는다. 표기가 틀리면 표기 버그이지 밸런스 버그가
   아니다.
2. 역할은 **입장 조건·필수 조합이 아니다.** 어떤 콘텐츠도 특정 역할 보유를
   요구하지 않는다. 역할이 빈 파티는 라운드와 HP를 조금 더 쓸 뿐 완주할 수 있고,
   이것은 시뮬레이션 합격 조건이다.
3. **등급과 역할은 독립이다.** 치유 담당이 상위 등급에만 있는 구조를 만들지
   않는다. 무료 뽀또가 지킴 주 역할과 돌봄 부 역할을 가져, 씨앗 0으로도 두 축을
   커버한다.
4. 역할이 가장 크게 드러나는 무대는 **6인 합동 수호전**이며
   `docs/guardian_raid_design.md`가 정의한다. 일반 3인 수호전에서는 배지·추천
   문구로만 드러나고 별도 판정이 없다.

| 역할 | 하는 일 | 주 역할 | 부 역할 |
|---|---|---|---|
| 지킴 | 예고 공격을 받아 내고 파티가 잃을 HP를 줄인다 | 뽀또, 가시로 | 시들잎 |
| 돌봄 | 깎인 HP를 복구하고 무너진 흐름을 일으킨다 | 블루미 | 뽀또 |
| 이음 | 집중력과 명령 순서를 이어 다음 대원을 키운다 | 로제온, 하루 | 별솔 |
| 달램 | 수호짐승의 위력을 낮추고 시선을 옮긴다 | 여우비 | — |
| 밝힘 | 약점·의도를 읽고 파티의 성장결을 정렬한다 | 별솔 | 여우비, 그림싹, 설화 |
| 매듭 | 열린 기회에 결정타를 넣어 장벽을 닫는다 | 시들잎, 그림싹, 설화 | 가시로 |

- 배정 근거는 6.3의 고유 II 효과다. 뽀또(전원 방어)·가시로(자기 방어·반사)는
  지킴, 블루미(최저 HP 회복)는 돌봄, 로제온·하루(집중력 환급·증폭)는 이음,
  여우비(적 위력 감소·재지정)는 달램, 별솔(약점·성장결 변환)은 밝힘,
  시들잎(저체력 강타)·그림싹(약점 폭발)·설화(방어 무시 마무리)는 매듭이다.
  역할 재배정은 스킬 rework와 같은 절차(14장)를 밟는다.
- 달램이 여우비 하나뿐인 것은 의도된 희소성이다. 대신 모든 수호전·합동
  수호전은 달램 없이도 9.2의 승률 밴드 안에 있어야 하며, 이것을 시뮬레이션
  축으로 검증한다.
- UI 배지는 주 역할 1개 + 부 역할 최대 1개를 아이콘과 단어로 함께 표시하고 색만으로
  구분하지 않는다. 상점에서는 5.2의 조작 성격 문구와 나란히 적는다(`돌봄 · 안정형`).
- 파티 추천은 역할 조합(예: 지킴 1·돌봄 1·매듭 1)을 제안할 수 있으나 제안일
  뿐이며, 따르지 않아도 어떤 페널티·경고도 없다.
- 5.5의 2,592환경/5,184명령 상태와 16.5의 10,000 seed 시뮬레이션 리포트는 역할 축 슬라이스를
  포함한다. 돌봄·달램의 기여는 피해량이 아니라 **승률·전멸률·평균 라운드 변화**로
  측정하고, 피해량 순위표를 사용자에게 노출하지 않는다.

### 6.7 감정 성장과 전투 속성의 연결

탐험 판정의 `care|focus|courage|insight`는 네 **행동 능력치**이고, 전투의
`sunny|rainy|ember|moonlit|sparkling|mosaic`는 여섯 **마음결 속성**이다. 이름이
비슷한 공명 시스템을 따로 만들지 않는다. 전투 UI·콘텐츠·로그는 여섯 성장결을
단일 원본으로 사용한다.

- stage 3에서 안정 주결이 정해지면 `emotion.primary`가 열린다. 분석 표본이 부족하거나
  사용할 수 없는 동안에는 동급의 `mosaic.join-heart`를 임시로 제공해 전투 선택지가
  줄지 않는다. 이를 실패·낮은 등급으로 표현하지 않는다.
- stage 4에서 14% 이상으로 공개된 보조결이 있으면 `emotion.secondary`가 열린다.
  보조결이 없다고 새 일기를 특정 감정으로 쓰라고 권하거나 진행 막대·미완성 경고를
  보여 주지 않는다. B2에는 기록서를 장착할 수 있고 모든 필수 전투는 보조결 없이
  같은 승률 밴드를 통과한다.
- 활성 캐릭터의 주결·보조결이 바뀌면 **다음 run부터** 포인터가 새 family로 해석된다.
  진행 중 run은 시작 snapshot을 유지한다. 수확 뒤에는 당시 고정 profile을 사용한다.
- 기본 공격·고유 I·고유 II는 기본적으로 주결 속성을 쓴다. `prism_shift`처럼 변환을
  명시한 스킬만 확정 전에 보이는 다른 속성으로 바꾼다. 감정 스킬은 자기 family의
  속성을 사용하고, 기록서는 catalog의 `affinity_code` 또는 `neutral`을 사용한다.
- 20개 시각 원소를 `ELEMENT_KEL`로 여섯 성장결에 매핑한다. 약점결이면 최종 장벽
  피해 `×1.50`, 내성결이면 `×0.60`(최소 1), 중립이면 `×1.00`이다. 회복·방어·
  집중력 수치는 상성으로 증감하지 않는다. 숨은 명중률·치명타·속성 확률은 없다.
- 여섯 결은 모두 같은 effect budget과 획득 시점을 가진다. 몬스터 약점·내성 출현 수도
  결마다 같게 유지하고, 결별 표준 파티 승률 편차가 ±2%p를 넘으면 수치·적 배치를
  조정한다. 사용자의 감정을 유리한 답으로 유도하지 않는다.

### 6.7.1 감정은 전술 언어이지 붕괴 게이지가 아니다

2026년 최신 RPG 일부는 스트레스·붕괴처럼 감정 상태를 전투 손실과 직접 연결한다.
몽그루는 감정이 전투 규칙과 연출을 바꾼다는 장점만 가져오고, 사용자의 기록을 벌점으로
되돌리는 구조는 명시적으로 배제한다.

- 마음결은 약점·내성·스킬 family·actor pose·접촉 재질을 바꾸지만 HP 감소, 부상,
  행동 불능, 합성 실패율, 보상 감소를 만들지 않는다.
- 진행 중 전투는 시작 snapshot의 결을 사용한다. 새 일기 분석이나 안전 분류가 전투 중
  난도·상성·AI를 바꾸지 않는다.
- `rainy`, `ember`, `moonlit`을 우울·폭주·공포의 디버프로 부르지 않는다. 각 결은
  경청·용기·준비라는 동등한 전술 역할을 가진다.
- 캐릭터 획득 전후의 20~30초 무보상 연습장에서 고유 I·II, 대표 약점 접촉, 지키기를
  시험할 수 있다. 등급과 구매 여부에 따라 연습 기능을 제한하지 않는다.
- 연습장과 스킬 상세는 실제 runtime sprite·SFX를 사용한다. 아이콘·PV만 멋있고 실전
  공격이 다른 구성을 금지한다.

시장 사례와 배제 판단의 단일 원본은 `adventure_game_trend_review_2026.md`다.

### 6.8 감정 스킬 6종 — 탐험과 전투의 같은 family

탐험 효과는 `interactive_adventure_design.md` 7.1을 유지한다. 아래는 B1/B2에 장착했을
때의 전투 payload다. 여섯 스킬 모두 집중력 1, 전투당 1회, 등급 계수 미적용,
`effect_budget=1`이다.

| 성장결 | canonical family | 전투 원시값 | 전투 효과 | 플레이 감각 |
|---|---|---:|---|---|
| 햇살결 `sunny` | `sunny.share-warmth` 온기 나누기 | P8 / 1 | 공격 후 최저 HP 대원 1 회복 | 넓게 품고 다시 일으킴 |
| 빗물결 `rainy` | `rainy.listen-echo` 잔향 듣기 | P8 / 1 | 이번 라운드 적 의도 위력 −1 | 공격의 울림을 듣고 누그러뜨림 |
| 불씨결 `ember` | `ember.open-path` 막힌 길 열기 | P12 / 1 | 부가 효과 없음 | 가장 높은 순수 장벽 돌파 |
| 달빛결 `moonlit` | `moonlit.look-ahead` 미리 살피기 | P8 / 1 | 선택한 대원 방어 +2 | 위험을 읽고 한 명을 준비시킴 |
| 별빛결 `sparkling` | `sparkling.side-path` 뜻밖의 샛길 | P9 / 1 | 다음 행동이 다른 속성이면 장벽 피해 +3 | 서로 다른 결을 이어 연계함 |
| 모아결 `mosaic` | `mosaic.join-heart` 마음결 잇기 | P9 / 1 | 다음 행동이 내성에 맞아도 중립으로 처리 | 불리한 결을 안전하게 이어 줌 |

같은 이름의 탐험·전투 스킬은 별도 수집품이 아니다. 하나의 family가 공간별 닫힌
payload를 가지며 아이콘·모티프·숙련 기록도 공유한다. 다만 사용 횟수는 탐험과 전투
각각 자기 run snapshot에 따로 저장해 한쪽 사용이 다른 쪽 charge를 소모하지 않는다.

전투 아이콘에는 감정 이름을 글자로 상시 쓰지 않고 10.4의 서로 다른 여섯 형태 glyph를
오른쪽 아래에 붙인다. 스킬명·원시값·현재 상성·효과 전문은 길게 누르기 상세에서만
보이며, 짧게 탭하면 설명 패널 없이 대상 선택 또는 즉시 실행으로 이어진다.

## 7. 마음결 기록서 — 스킬북

### 7.1 기본 계약

- 기록서는 **계정 귀속 영구 라이선스**다. 소모되지 않고, 파괴되지 않으며, 강화·합성·
  분해가 없다. 의상과 같은 취급이다.
- 같은 코드의 기록서는 계정에 한 장이다. 여러 캐릭터 프리셋에 저장할 수 있지만
  출발하는 한 파티에서는 한 번만 쓴다. 장착 변경은 run 밖에서 무료·무제한이다.
- 모든 기록서는 `reward_affecting: false`다. XP·씨앗·수집품 수량·가치 예산·확보 슬롯
  칸 수를 바꾸는 효과는 만들 수 없다.
- 기록서는 확률로 나오지 않는다. 세 획득 경로 모두 결정적이다.
- 전투형 책은 `activation_mode=command|opening|trigger` 중 하나를 명시한다.
  `command`는 대원의 한 행동을 쓰고, `opening`은 첫 라운드 명령 전에 한 번,
  `trigger`는 표에 적힌 공개 조건에서 자동 발동한다. 모드를 런타임에서 추측하지 않는다.

### 7.2 등급과 슬롯

| 등급 | 이름 | `effect_budget` | 장착 가능 슬롯 | 획득 경로 | 초기 종수 |

#### 7.5.1 전투 기록서 activation 단일 원본

효과 문장에서 모드를 추측하지 않는다. 초기 combat 20종의 mode는 다음 닫힌 목록이다.

| mode | code | 실행 규칙 |
|---|---|---|
| `command` | `short_cheer`, `echo_read`, `resonance_tuner`, `reviving_root`, `weakness_engrave`, `nine_tail_afterimage`, `heart_encyclopedia` | 대원 행동 1회 소비. 1등급 집중 0, 2등급 1, 3등급 2, 전투당 1회 |
| `opening` | `first_breath`, `first_signal`, `bellringer_chime`, `germination_gear`, `ringcount_record`, `shadow_oath` | 첫 라운드 의도 공개 뒤 명령 전에 B1→B2, 파티 순서로 1회 해결 |
| `trigger` | `leaf_greave`, `clear_aim`, `bracing`, `final_resolve`, `double_leaf`, `focus_knot`, `steady_axis` | 표의 공개 조건을 만족한 첫 합법 행동에 전투당 1회. 조건 전에는 `대기` |

- 탐험형 16종은 사건·지도 문맥에서만 `command`이며 전투 아이콘에는 빈 책 윤곽으로
  나타난다. 수호 프리셋에서 탐험형 책을 장착해도 출발을 막지는 않지만 파티 준비가
  `이 기록서는 전투에서 쉬어요`라고 정확히 알려 준다.
- `opening`·`trigger`가 효과를 냈다고 대원 행동을 소비하지 않는다. 대신 같은
  `stack_group` 충돌·charge 차감·로그·SFX는 일반 command와 같은 서버 원장을 쓴다.
- 신규 기록서는 이 닫힌 목록과 콘텐츠의 `activation_mode`를 함께 갱신해야 하며,
  클라이언트가 문구 키워드로 mode를 추론하지 않는다.

### 7.6 획득 경로 세 가지의 역할 분담

| 경로 | 비중 | 내역 | 무엇을 보상하나 | 리스크 |
|---|---:|---|---|---|
| 상점 구매 | 20종 | 1등급 14 + 2등급 6 | 꾸준한 기록으로 모은 씨앗 | 씨앗 인플레 — 8.2의 소비 곡선으로 관리 |
| 해금 조건 | 8종 | 2등급 8 | 특정 플레이 습관을 끝까지 해 본 경험 | 조건이 불명확하면 그라인딩이 됨 — 전부 사전 공개 |
| 도전 고정 달성 | 8종 | 던전·개척 5 + 숙련·수집 3 | 어려운 콘텐츠와 오래 쓴 조합 | 확률·반복 강요 — 전부 **계정 1회**, 재획득 없음. 5종은 획득 전 지역 힌트만 |

세 경로 어디에도 확률, 일일 횟수 제한, 기간 한정이 없다. 오늘 못 얻은 기록서는
내일도 같은 조건으로 얻을 수 있다. `hinted_until_acquired`는 조건을 없애는 정책이
아니라 클라이언트에 정확한 이름·효과·조건을 언제 직렬화할지 정하는 공개 정책이다.

B1 첫 선택은 상점 1등급 14종 중 지정된 세 권 한정으로 **개인별 첫 획득 가격을 0으로 바꾸는
온보딩 규칙**이다. 카탈로그의 주 획득 경로 종수 20+8+8은 바뀌지 않으며,
획득 규칙을 단일 `acquire_kind` 컬럼으로 표현하지 않는 이유도 여기에 있다.

## 8. 재화와 경제

### 8.1 새 통화를 만들지 않는다

기록서·회향·진화 어디에도 새 통화, 강화석, 승급 재료, 티켓을 만들지 않는다.
씨앗 하나와 이미 존재하는 탐험 수집품(연구용)만 사용한다. 회향 권리는 주간 일기
목표가 직접 발급하며 거래·구매·변환할 수 없다.

### 8.2 씨앗 수입과 지출 곡선

| 수입원 | 1일 | 1주 |
|---|---:|---:|
| 50자 마음 일기 | 15 | 105 |
| 일일 미션 | 5 | 35 |
| 자동 순찰 귀환 | 3 | 21 |
| 당일 보상 직접 탐험 (지역별 2~5) | 2~5 | 14~35 |

| 7일 누적 기록 | — | 30 |

| 지출 | 총액 | 누적 도달 시점 |
|---|---:|---|
| 캐릭터 9종 해금 (50~180) | 970 | 전 수입 집중 시 약 4주 |
| 1등급 기록서 14종 × 40 | 560 | 약 2.2~2.4주 |

  걸린다. 그 뒤에도 pack이 6주마다 기록서 4종을 추가하므로 목표가 완전히 마르지 않는다.
- 위 합계는 매일 모든 활동을 한 이론값이다. 실제 경제 예측은 7일·30일 활동률
  cohort의 중앙값과 P25/P75를 함께 사용하고, 상점 가격을 이론 최대 수입에 맞추지 않는다.
- 구버전 즉시 던전과 새 직접 탐험을 같은 날 모두 완료해도 경제 보상은 한 lane만
  지급한다. `adventure_reward:{user}:{local_date}` 원장이 먼저 완료된 쪽을 기록하고
  다른 쪽은 자유 탐험으로 전환한다. 마이그레이션 기간의 이중 지급을 가격에 반영하지 않는다.
- 기존 꾸미기 상품과 경쟁하지 않도록 기록서는 상점의 **별도 탭**에 두고, 홈 화면
  배지로 구매를 재촉하지 않는다.
- 씨앗이 부족해도 진행이 막히지 않는다. 기록서를 한 권도 사지 않은 캐릭터로 모든
  필수 경로와 수호전을 완주할 수 있어야 하며, 이것은 시뮬레이션 합격 조건이다.

- 기록서 중복 지급 후 합성·분해로 되파는 구조
- 미보유 기록서의 성능을 상점에서 과장하는 문구
- 특정 캐릭터를 사야만 열리는 필수 경로·필수 재료·주간 목표

## 9. 수호자 스케일링

> **2026-08-10 개정 공지** — 9.1의 장벽 계수와 5장의 tier 규칙은
> `docs/expedition_combat_core_design.md`가 우선한다. 상성이 곱연산으로 바뀌면서
> 장벽 계수는 `0.30`(상한 1.30)으로 확정했다. T2는 위력 110%만 적용하고 CD를
> 줄이지 않으며, T3에서 고유 II만 `3→2`로 줄인다.

### 9.1 성장을 상쇄하지 않는다

파티가 강해진 만큼 적도 강해지면 성장한 이유가 사라진다. 반대로 적이 전혀 안 따라오면
후반 지역이 무의미해진다. 몽그루는 적 전체가 아니라 **수호자 장벽만 최대 30%까지
완만하게 증가**시킨다. 적 공격력은 성장지수를 읽지 않으며, 레벨·tier·희귀도에서 얻은
파티 성장 우위의 대부분은 사용자에게 남는다.

```text
G = 파티 실제 소유 대원의 평균 성장지수 (0~100)
성장지수 = round((level - 1) / 29 * 100)
길잡이는 G 계산에서 제외한다. 전원이 길잡이면 G = 0이다.
B = max(0, G - 10) / 90

guardian_barrier = base_barrier * (1 + 0.30 * B)
guardian_power   = 지역·난이도 고정값. G를 읽지 않는다.
```

`G≤10`(대략 Lv1~3)은 계수 반올림상 플레이어 위력이 아직 오르지 않을 수 있으므로
장벽을 늘리지 않는다. 그 이후만 1.00→1.30으로 보간해 초반 역성장을 막는다.

| 파티 구성 | 평균 레벨 | G | 파티 위력 지수 | 장벽 배수 | 순 우위 | 정책 시뮬레이션 |
|---|---:|---:|---:|---:|---:|---|
| 등급 1 Lv 5 1명 + 길잡이 2 | 5 | 14 | 100 | 1.013 | 0.987 | 미측정 |
| 등급 2~3 Lv 16 2명 + 길잡이 1 | 16 | 52 | 138 | 1.140 | 1.211 | 미측정 |
| 등급 4~5 Lv 28 3명, `B1`·`B2` 장착, T3 | 28 | 93 | 196 | 1.277 | 1.535 | 미측정 |

순 우위는 설계 입력의 산술 예시이지 승률·라운드 측정 결과가 아니다. 1라운드는
집중력을 만드는 데 대부분 쓰이고 라운드는 정수로만 끝나므로, 실제 P10/P50/P90은
16.5와 `expedition_combat_core_design.md` 10장의 정책 시뮬레이션으로만 확정한다.

- 적 위력은 성장을 읽지 않으므로 HP 상승이 그대로 안전 마진이 된다. 오래 키운 파티가
  전멸할 걱정 없이 지휘에 집중할 수 있다.
- 합격 목표는 스테이지 역할별로 나눈다. 튜토리얼은 승률 100%·P90 1~2라운드,
  일반 2웨이브는 P50 2~4라운드, 큰 엉킴은 P50 2~4라운드, 혼합 숙련은 P50
  3~6라운드다. 1라운드 완료 금지는 튜토리얼이 아닌 전투에만 적용한다. 장벽 배수
  하한 1.0, 상한 1.30은 유지한다.
- 기본 6라운드 상한과 긴급 귀환 규칙은 그대로다. `bellringer_chime`을 장착한
  snapshot만 집중력 최대치 −1과 맞바꿔 7라운드를 허용한다. 그 밖의 스킬·난이도·
  등급은 상한을 늘리지 못하며, 실패해도 캐릭터는 손실·퇴화하지 않는다.

### 9.2 난이도별 긴장감

모든 난이도를 90% 승률로 맞추면 직접 지휘의 의미가 사라진다. 필수 진행은 막지 않되
선택 도전은 실제 실패 가능성을 남긴다.

| 난이도 | 대상과 용도 | 권장 조건의 첫 도전 승률 | 실패 결과 | 전용 경제 우위 |
|---|---|---:|---|---|
| `gentle` 편안한 이야기 | 필수 경로, 신규 캐릭터·길잡이 | 90~100% | 확보 기록 보존 후 안전 귀환 | 없음 |
| `standard` 표준 조사 | 일반 반복, 직접 지휘 학습 | 70~90% | 핵심 발견 보존, 미확보 후보만 놓침 | 없음 |
| `deep` 깊은 조사 | 숙련 조합·3등급 기록서 최초 달성 | 45~70% | 재도전 가능, 캐릭터·XP·씨앗 손실 없음 | 최초 기록서·서사만, 반복 재화 증가 없음 |
| 숙련 재방문 | 조건과 적 패턴을 학습한 뒤 | 80~95% | 위와 같음 | 없음 |

- `gentle`만 필수 진행의 합격선으로 쓴다. `deep`의 낮은 첫 승률을 전체 평균에 섞어
  신규 사용자 실패처럼 보고 난도를 자동 하향하지 않는다.
- 깊은 조사도 등급 1 캐릭터로 완주할 수 있어야 한다. 높은 등급은 요구 조건이 아니라
  같은 성장 시간에서 선택 여유와 성공 확률을 조금 높이는 수단이다.
- 적 의도·약점·예상 피해는 확정 전에 공개한다. 실패 가능성은 숨은 확률이 아니라
  사용자가 읽고 감수한 선택에서 나온다.

### 9.3 체감 성장의 진짜 출처

숫자 배수는 전체 체감의 일부다. 실제로 "강해졌다"고 느끼게 하는 것은 다음 순서다.

1. 명령 벨트가 2개(공격·방어)에서 6칸(공격·방어·고유 I·고유 II·선택 스킬 2)으로
   자란다. 선택한 기록서가 `command`면 직접 행동은 최대 6개, `opening|trigger`여도 장착·발동
   상태와 전용 연출이 같은 자리에 남는다.
2. HP 3 → 6으로 한 번 맞아도 되는 여유가 생긴다.
3. 시작 집중력 3 → 4로 첫 라운드부터 스킬을 쓸 수 있다.
4. 고유 스킬의 이름·연출·범위가 두 번 바뀐다.
5. 그 결과로 장벽이 눈에 띄게 빨리 깎인다.

## 10. 연출·에셋·오디오 계약

### 10.1 희귀도는 밝기가 아니라 전용 제작량을 산다

열 품종은 길·수호 스킬마다 **고유한 실루엣, 시동 동작, 타격 모티프, 짧은 음색**을
가진다. 낮은 등급도 공용 색상 교체로 끝내지 않는다. 희귀도가 높아질수록 조건 변형과
마무리 레이어가 늘어나지만, 화면 점유 시간·섬광·흔들림을 늘려 성능이 더 좋아 보이게
만들지는 않는다.

| 등급 | 제작 범위 | 공용 포함 최대 합성 레이어 |
|---:|---|---:|
| 1 | 성장결 공용 몸체 + 품종 고유 모티프 | 2 |
| 2 | 품종 전용 시동·모티프 + 공용 타격 재질 | 3 |
| 3 | 품종 전용 시동·궤적·타격 | 3 |
| 4 | 품종 전용 3층 + 조건 충족 변형 | 4 |
| 5 | 품종 전용 3층 + T3 흐름·마무리 | 4 |

전 등급의 런타임 예산은 동일하다.

- 일반 행동 620~900ms, 결정기 950~1,400ms, 타격 정지 45~80ms
- 공격 본체 실제 표시 폭 72~192px, 화면 면적 35% 이하, 동시 파편 최대 12개
- 화면 흔들림 2.8~3.5px 단일 구간
- 짧은 연출에서도 비행·접촉·피격 반응을 생략하지 않고 입력 잠금 900ms 이하

#### 10.2.1 스킬 아이콘 ImageGen 제작 계약

고유 60·감정 6·기록서 36개는 단색 glyph를 확대해 만든 임시 아이콘이 아니라
**ImageGen 기반 도색 아이콘 master**를 각각 가진다. 기본 공격·마음 지키기·AUTO처럼
게임 전체에서 의미가 고정된 시스템 조작만 기존 semantic SVG를 유지한다.

- master는 1024×1024 정사각 PNG, 런타임은 128×128 WebP와 저사양용 64×64 WebP다.
  아이콘 그림은 정사각 안을 채우고 UI가 라운드 마스크를 적용한다. 테두리·잠금·비용·
  횟수·tier·상성 화살표는 앱 오버레이이므로 원본 이미지에 굽지 않는다.
- 한 호출에는 아이콘 하나만 생성한다. 여러 아이콘 grid, 60개 접촉 시트, `n` 변형으로
  서로 다른 스킬을 한꺼번에 만들지 않는다. 고유 T1을 승인한 뒤 T2·T3는 앞선 승인
  아이콘을 참조한 edit/generate로 실루엣을 유지하고 모티프 한 층만 발전시킨다.
- 입력 이미지는 역할을 명시한다. Image 1은 프로젝트 아이콘 스타일 보드, Image 2는
  캐릭터 또는 기록서 모티프 참조, Image 3은 이전 tier 승인 아이콘이다. T1·감정·기록서
  최초 호출에는 Image 3을 넣지 않는다.
- 한 개의 큰 주모티프가 화면의 58~72%를 차지하고 12% safe margin을 남긴다. 얼굴·
  전신 캐릭터·전장 배경·UI 프레임·글자·숫자·워터마크·여러 장면을 넣지 않는다.
- ImageGen 결과는 `$CODEX_HOME/generated_images/`에만 두지 않고 승인 즉시 프로젝트의
  `design-system/concepts/character-skill-vfx-v1/icons/sources/`로 복사한다. 사람
  paint-over와 색상 정리 뒤에만 runtime builder가 읽는다.
- 아이콘이 full-bleed 도색 배경을 가지므로 기본 경로에는 투명 출력이 필요 없다.
  cutout 방식이 필요한 예외만 10.2의 크로마 제거·alpha QA를 사용하고, true-alpha CLI로
  자동 전환하지 않는다.
- 128·64·48·32px 접촉 시트, 흑백, 저채도, 6종 전장 배경 위에서 검수한다. 48px에서
  1초 안에 S1/S2와 장착 스킬을 구분하지 못하거나 색만 바꾼 두 아이콘은 반려한다.

제작은 `6칸 실루엣 콘티 → 캐릭터·배경 팔레트 참조 → ImageGen 승인 키프레임 →
투명 RGBA 정리 → 2D in-between → actor/flight/impact/reaction 합성 QA` 순서다.
프레임마다 무참조로 독립 생성하거나 완성 8~12프레임 시트 한 장을 한 번에 생성하지
않는다. 덩굴 굵기·마디 수·불씨 개수·문양 중심·광원이 흔들려 동작이 녹기 때문이다.

ImageGen에는 한 호출당 `시동`, `비행 50%`, `첫 접촉`, `최대 impact`, `소멸` 중 한
키프레임만 요청한다. 첫 키프레임에는 승인 캐릭터·배경·모티프 보드를, 다음 호출부터는
앞선 승인 키프레임도 참조로 넣는다. 내장 ImageGen은 native alpha를 가정하지 않고,
family 팔레트와 겹치지 않는 완전 평면 chroma(`#FF00FF` 또는 `#00FF00`)를 중간
원본으로 만든다. 설치된 `remove_chroma_key.py`의 soft matte·despill 경로로 제거한 뒤
alpha channel·투명 모서리·key fringe 0을 검증한 결과만 RGBA master로 승인한다. 최종
master에는 배경색·체커보드·캐릭터·바닥·UI가 한 픽셀도 남아서는 안 된다. 반투명 재료로
true native alpha가 꼭 필요할 때만 제작 책임자의 명시적 승인 뒤 CLI fallback을 검토한다.

예를 들어 덩굴 공격은 `말린 새순 → 뻗는 줄기 → 화면 중간의 굵은 덩굴 → 타깃을
감는 덩굴 → 잎 impact → 풀려 돌아가는 끝`의 모양 잠금을 먼저 승인한다. 코드는
완성 덩굴을 그리지 않고 승인 프레임을 origin/target anchor 사이로 이동시키는 일만
한다. 불꽃·서리·칼날·물결과 몬스터 공격도 같은 절차를 쓴다.

원본과 앱 산출물은 섞지 않는다.

이 표는 플레이어 고유·감정·기록서 수량만 센다. 일반 엉킴 12종과 수호짐승 4종의
몸체·예고·공격·피격·풀림 수량은 `expedition_stage_redesign.md` S3A와 에셋 실행서가
별도로 소유하며, 적 에셋이 빠졌다고 플레이어 에셋만으로 M2를 완료 처리할 수 없다.

### 10.3 품종별 시각·청각 언어

기존 `app/assets/adventure/effects/`의 여덟 효과군은 prototype 비교 자료로만 보존한다.
완성 시트를 한 번에 생성한 원본과 공용 `enemy_wave`는 v1.3 정식 스킬의 타격 본체로
재사용하지 않는다. 아래 모티프를 품종마다 새로 키프레임화한 결과가 최종 실루엣이다.

모티프의 주인공은 식물이 아니라 **품종의 캐릭터 컨셉** — 아기, 온실 수석, 무대
아이돌, 경비대, 야간 근무, 신사의 요괴, 닌자, 학생회장, 마법학원, 연구소 — 이다.
열 품종의 스킬이 전부 잎·덩굴·꽃잎으로 수렴하면 품종 구분이 무너지고 연출이
단조로워진다. 식물 요소는 품종을 몽그루답게 만드는 **서명 한 조각**으로 축소해
남긴다. 서명은 한 행동에 1회, 시동 또는 마무리 한 자리에만 넣고 타격 본체를
식물로 대체하지 않는다.

| 품종 | 컨셉 주모티프 | 식물 서명 | 고유 움직임 | 짧은 음색 |
|---|---|---|---|---|
| 뽀또 | 폭신한 싸개 담요와 아기 손짓 | 새싹 잎 3장 | 잎 3장이 감싸며 닫힘 | 부드러운 목금 |
| 로제온 | 지휘봉 선, 온실 유리 빛면, 열쇠 문양 | 푸른 장미 꽃잎 | 손짓 뒤 선이 세 갈래로 전개 | 낮은 현 긁기 |
| 블루미 | 스포트라이트, 무대 조명 바, 응원봉 궤적 | 큰 꽃잎 3장의 꽃가루 | 스팟이 두 곳으로 갈라짐 | 유리종과 무대 큐 |
| 가시로 | 경비 초소 창살, 반사 파편, 순찰 랜턴 | 선인장 가시 | 가드 직후 궤적이 되튐 | 마른 현 튕김 |
| 시들잎 | 야간 순찰 랜턴, 출석 도장, 그림자 손 | 되살아나는 시든 잎 한 장 | 손이 붙잡고 잔상이 뒤늦게 닫힘 | 숨 섞인 저음 |
| 여우비 | 여우불, 부적 조각, 신사 방울과 매듭 끈 | 꼬리 끝 잎사귀 | 매듭이 아홉 갈래로 풀림 | 짧은 피리와 방울 |
| 그림싹 | 잎 수리검 두 획, 연막, 잔상 대시 | 새싹 문양 각인 | 대시 뒤 약점 각인이 남음 | 종이 베는 소리 |
| 하루 | 수첩 격자, 체크 도장, 당번표 | 책갈피 잎 | 격자가 정렬되고 한 칸씩 점등 | 연필과 클릭 |
| 별솔 | 별 마법진, 지팡이 궤적, 별자리 선 | 별 모양 잎 | 결정 3개가 순서대로 굴절 | 맑은 신스 벨 |
| 설화 | 서리 결정, 유리 플라스크, 관측 기록 카드 | 동백 꽃잎 | 보호면이 얼고 꽃잎이 느리게 낙하 | 얼음·도자기 |

- 컨셉 주모티프는 6.4의 이름·6.5의 문구와 같은 단어를 쓴다. `개막 지휘`라는
  이름의 연출에 무대 막이 없거나, `아홉 번째 장난`에 방울·부적이 없으면 아트 QA
  차단 결함이다.
- 식물 서명이 0인 품종도, 식물이 본체인 품종도 만들지 않는다. 뽀또만 예외적으로
  잎이 본체에 가깝다. 아기 화분이라는 컨셉 자체가 새싹이기 때문이다.
- 이 표의 품종 주모티프와 10.4의 감정 속성 레이어는 독립이다. 품종 실루엣을 유지한
  채 작은 마음결 glyph·재질만 얹고, 실제 약점·내성 계산은 서버 `affinity_code`가 맡는다.

#### 10.3.1 진화 tier별 연출 내용 명세

  피격 판정 창을 바꾸지 않는다.
- 수호 T3 동작 12프레임은 신규 시트지만 시동 실루엣과 pivot·동선은 T1과 같아야 한다.
  "버튼 개수와 조작 방법은 바뀌지 않는다"는 4.1의 약속은 손에 익은 시동 동작에도
  적용된다.
- 등급 4~5의 조건 충족 변형은 이 표의 마무리 레이어 밀도만 높인다. 화면 점유 시간·

  차단 결함이다.

### 10.4 감정 속성 glyph와 오버레이

`sunny`, `rainy`, `ember`, `moonlit`, `sparkling`, `mosaic` 여섯 마음결은 고유
스킬·감정 스킬 아이콘과 공격 위에 작은 보조 레이어를 얹는다. 색각에 의존하지 않도록 sunny는 둥근 확산,
rainy는 아래로 흐르는 점, ember는 뾰족한 상승, moonlit은 얇은 초승달,
sparkling은 네 갈래 반짝임, mosaic는 분할 격자로 형태도 구분한다.

오버레이 자체가 위력·타이밍·피격 범위·프레임 수를 바꾸지는 않는다. 약점·내성 판정은
snapshot의 `affinity_code`로 서버가 계산하며, 오버레이 로딩 실패로 상성이 중립이 되거나
바뀌지 않는다. 이때 기본 타격 프레임과 텍스트 `약점/내성`으로 안전하게 폴백한다.

### 10.5 기록서 표현

- 기록서 36종은 상점과 도감에서 구분되는 고유 표지를 가진다.
- 전투 동작은 역할별 12개 공용 모듈을 쓰고, 표지의 문양 한 조각만 타격 모티프로
  가져온다. 전 품종 고유 스킬보다 시각 우선순위가 낮아야 한다.
- 3등급 기록서 8종은 적·아군이 대응할 수 있도록 발동 120ms 전에 고유 경고
  오버레이를 보여 준다.
- 기록서 획득 연출은 도서관에서 900ms 이내로 끝낸다. 큰 빔·전면 백색 섬광으로
  희귀도를 표현하지 않는다.

### 10.6 오디오 계약

품종별 고유 I·II 모티프 cue 20개를 제작한다. 같은 품종의 두 스킬은 재료 정체성을
공유하되 envelope·transient·contact phrase 중 둘 이상이 달라야 한다. T1은 모티프 단독,
T2는 보조음 한 층, T3는 짧은 종결음을 더한다. 감정 스킬은 여섯 결 cue 6개, 기록서는
역할별 공용 cue 8개를 사용해 총 34 stem/cue를 가진다.

- 제작 원본: 48kHz / 24bit / mono WAV
- 앱 산출물: 플랫폼별 압축 포맷, true peak -2dBTP 이하, 효과음 -20~-16 LUFS
- 동시 재생 최대 4개, 같은 키 재트리거 간격 80ms
- 효과음·햅틱·화면 흔들림을 각각 끌 수 있고 무음에서도 판정 정보를 잃지 않음
- 타격음은 `impact_frame`과 동기화하고 프레임 드롭 시 오디오를 연속 재생하지 않음

### 10.7 런타임·메모리 예산

- 개별 프레임은 256×256 또는 최대 384×384 알파 WebP, 12~16fps, 내용 bbox로 크롭하고 pivot 고정
- 전투 진입 전에 파티 장착 고유·감정·기록서와 예상 적 스킬만 프리페치
- 전투 도중 파일 I/O 금지, 스킬 텍스처 LRU 캐시 24MiB
- 중급 기준 래스터 스레드 8ms 이하, 셰이더 컴파일 끊김 0회
- 큰 효과 동시 2개까지, 세 번째는 70ms 시차로 큐잉
- manifest 누락·해시 불일치·빈 알파 프레임은 CI에서 실패
- 검증된 pack의 런타임 디코드 실패는 해당 family의 `reduced_motion_frame`과 판정
  문장으로 대체하고 오류를 기록한다. 공용 impact나 코드 도형으로 공격 종류를 바꾸지 않는다.

### 10.8 접근성·아트 QA

- 진화·조건 충족·약점·내성은 색만으로 구분하지 않고 아이콘·glyph·화살표·숫자를 함께 쓴다.
- 조건 충족 이유를 명령 확정 전에 보여 준다. 스크린리더는 `고유·길`,
  `고유·수호`, `선택 1`, `선택 2` 순으로 읽는다. 선택 슬롯은 `감정 스킬` 또는
  `기록서` source를 이름 앞에 덧붙인다.
- `disableAnimations`에서는 `reduced_motion_frame` 한 장과 live region 문장으로
  대체한다. 조작 표적은 최소 48dp이며 320px 폭·200% 글자에서 2×2로 접힌다.
- 자동 검사: 선 굵기, 최대 휘도, 팔레트 수, 알파 fringe, 공중 파편, 프레임 pivot,
  빈 프레임, manifest 수량.
- 사람 검수: 배경 6종과 캐릭터 10종 위 합성, 실기기 60/90/120Hz, 밝기 20%와
  흑백 모드, 연속 발동 시 가독성.
- 거친 노이즈, 프레임마다 형태가 녹는 현상, 마젠타 잔여 픽셀, 과도한 미세 입자는
  출시 차단 결함으로 취급한다.

## 11. 데이터 모델

### 11.1 파생 값 — 테이블을 만들지 않는 것

레벨·stage·tier·계수는 테이블에 중복 저장하지 않는다. 서버 도메인 함수가 유일한
계산 주체이고 앱은 서버가 내려 준 basis point와 최종 정수만 표시한다.

```text
base_level_from_exp(exp) -> 1..30
effective_level(exp, status, reflection_levels) -> 1..30
stage_from_exp(exp) -> 1..5
maturity(stage, effective_level) -> 0 | 1
signature_tier(stage, effective_level) -> 1 | 2 | 3
rarity_scale_bp(effective_level, rarity) -> int
basic_rarity_bp(rarity_scale_bp) -> int
growth_index(effective_level) -> 0..100
```

`plants`에는 오직 수확 뒤 느린 성장을 나타내는 `reflection_levels smallint NOT NULL
DEFAULT 0 CHECK (reflection_levels BETWEEN 0 AND 29)`만 추가한다. `plant.exp`는 기존처럼
보존한다. `final_level`, `signature_tier`, `power_scale` 컬럼을 별도로 만들지 않는다.

스킬 family code와 tier도 분리한다. 운영 중인 family code를 바꾸지 않으며, 구버전
별칭은 코드의 닫힌 `skill_code_aliases` 맵에서 canonical code로 정규화한다.

### 11.7 주간 회향 권리

`weekly_reflection_entitlements`는 `(user_id, week_start)`를 복합 PK로 사용한다.
`claimed_plant_id NULL`, `earned_at`, `claimed_at NULL`을 저장한다.

- 서버 기준 주 시작일과 일기 3일 달성을 유일한 발급 근거로 삼는다.
- 같은 주의 재시도는 기존 행을 반환한다.
- 적용은 수확 상태·소유권·Lv30 미만을 한 트랜잭션에서 확인한 뒤
  `plants.reflection_levels`를 1 올리고 `claimed_plant_id`를 채운다.
- 실패하면 권리와 캐릭터 양쪽 모두 바뀌지 않는다. 미사용 권리는 만료되지 않는다.

### 11.8 기존 탐험 스냅샷 JSON

`expedition_party_members`에는 이미 암호화된 `snapshot` JSON이 있다. 전용 스냅샷
컬럼을 새로 만들지 않고 schema version을 올려 다음 필드를 그 JSON 안에 넣는다.
진행 중 run은 이후 밸런스 패치나 프리셋 변경의 영향을 받지 않는다.

| JSON 필드 | 타입 | 의미 |
|---|---|---|
| `schema_version` | int | 이 문서 적용본은 4 |
| `base_level` | tinyint | exp로 계산한 1~30 |
| `level_snapshot` | tinyint | effective level 1~30 |
| `reflection_levels` | tinyint | 시작 시점 값 |
| `signature_tier_snapshot` | tinyint | 1~3 |
| `signature_codes_snapshot` | json | `S1`·`S2` canonical family code |
| `signature_1_battle_charge_max_snapshot` | tinyint | v1.3은 1 |
| `emotion_affinities_snapshot` | json | `primary`, 선택 `secondary`, 각 form code와 glyph key |
| `rarity_scale_bp_snapshot` | int | 고유 위력 basis point |
| `basic_rarity_bp_snapshot` | int | 기본 공격·고유 I basis point |
| `build_fingerprint` | varchar(64) | 스킬트리·프리셋·버전 해시 |

고유 I의 남은 전투 charge는 정의 snapshot이 아니라 변화하는 전투 상태이므로 기존
`runtime_effects_snapshot.guardian_battle.members[member_id].signature_1_charges`에 둔다.
명령 판정·charge 차감·`last_exchange` 기록을 한 트랜잭션으로 처리한다.

낡은 snapshot은 `schema_version=1|2|3` 어댑터로 읽는다. v2에는 고유 I 전투 charge가
없으므로 진행 중 run에서는 S1 전투 아이콘을 잠그고 기존 결과를 유지한다. v3 run은
네 공명 `weakness_cycle`과 `skill_book_snapshot`으로 끝까지 재생하고 감정 선택 스킬이나
내성을 소급 주입하지 않는다. 새 run만 v4의 여섯 성장결·고정 약점/내성·
`selected_skills_snapshot`으로 쓴다. 진행 중 snapshot을 일괄 재작성하지 않는다.

### 12.2 쓰기

| 메서드 | 경로 | 규칙 |
|---|---|---|
| `PUT` | `/plants/{plant_id}/skill-loadouts/{preset_code}` | 두 선택 슬롯(book code 또는 emotion pointer)과 `expected_revision`. 무료·무제한 |
| `POST` | `/shop/skill-books/{code}/purchase` | 잔액 확인·차감·보유 추가를 한 트랜잭션. `client_action_id` 멱등 |
| `POST` | `/skill-book-choice-entitlements/{id}/claim` | 허용 후보 하나를 확정. `client_action_id` 멱등 |
| `POST` | `/reflections/{week_start}/apply` | `plant_id`에 미사용 회향 적용. 수확 상태·Lv30 미만만 허용 |

프리셋 저장은 다른 캐릭터가 같은 책을 참조해도 성공한다. 응답은 새 `revision`,
source type, 서버가 정규화한 canonical 또는 emotion pointer를 돌려준다. 시작 전까지
재화·사용 횟수 원장은 없다.
같은 `client_action_id`의 구매·선택 재전송은 최초 성공 응답을 200으로 다시 돌려주고
`ALREADY_OWNED`로 바꾸지 않는다. 다른 action ID의 실제 중복만 409다.

### 12.3 탐험·전투 요청 확장

- 탐험 시작 요청은 대원마다 `preset_code`를 받는다. 서버가 emotion pointer를 현재
  profile로 resolve해 세 대원의 실제 장착 snapshot을 만들고, 같은 기록서 code가 둘
  이상이면 출발 전에 422로 거절한다. 같은 감정 family는 중복 가능하다.
- 탐험 문맥 행동은 기존 요청에 선택 필드 `skill_book_code`를 더한다. `skill_node_code`와
  동시에 보내면 422다. 한 확정 행동에는 스킬트리 또는 기록서 하나만 쓴다.
- 수호전은 기존 `POST /expeditions/{run_id}/combat/turns`의 `action: skill`에
  `skill_slot: S1|S2|B1|B2`와 서버가 확인할 `skill_code`를 함께 받는다. 구버전
  클라이언트가 둘 다 생략한 요청만 고유 II(`S2`)로 간주한다. 새 클라이언트는 표시
  아이콘과 다른 code를 임의 전송할 수 없고 snapshot 슬롯과 일치해야 한다.
- B 슬롯의 `skill_code`는 snapshot에 고정된 **resolved code**다. 앱이 행동 요청에서
  `emotion.primary|emotion.secondary` pointer나 다른 affinity를 다시 선택하지 않는다.
- `opening|trigger` 기록서는 `action: skill`로 제출할 수 없다. 서버가 라운드 시작·
  공개 trigger 조건에서 snapshot 순서대로 해결하고 `last_exchange`에 원인·효과를 남긴다.
- 클라이언트가 tier나 계수를 보내지 않는다. 서버는 시작 snapshot의
  `signature_tier_snapshot`과 bp를 사용한다. 별칭 code는 canonical로 바꾼 뒤 검증한다.
- 잘못된 code, 미장착 선택 스킬, 사용 횟수 소진, 조건 미충족, 순서상 집중력 부족은 전부 422다.
- 시작한 run은 `selected_skills_snapshot`을 따르며 도중 장착·주결·보조결 변경은 반영하지 않는다.
- `heart_encyclopedia` 교체 후보도 시작 때 `replacement_pool_snapshot`으로 고정한다.
  파티원이 이미 쓴 code와 현재 stack conflict 후보는 제외하며, 시작 뒤 새로 산 책을
  도중에 끌어오지 않는다.
- 결과 응답은 사용한 family code·tier·원시값·bp·조건 배수·최종 반올림 값을
  `calculation_trace`에 담아 리플레이와 고객 지원이 같은 결과를 재현하게 한다.

## 13. UI 계약

### 13.1 캐릭터 스킬 화면

- 4슬롯을 2×2 카드로 배치한다. 위 두 칸이 고유, 아래 두 칸이 선택 스킬이다.
- `탐험`, `수호`, `내 조합` 세 프리셋 탭을 상단에 둔다. 저장 상태와 서버 revision을
  표시하고 충돌하면 서버 값·내 값을 비교해 다시 선택하게 한다.
- 관리 화면의 접힌 카드는 아이콘·이름·source(`감정|기록서`)·tier/횟수까지만 표시하고
  효과 설명을 상시 펼치지 않는다. 짧게 탭하면 슬롯 선택/교체 목록만 열고, 350ms
  길게 누르기·키보드/스크린리더 `상세 보기`로 명시적으로 요청했을 때만 원시 효과,
  현재 계수, 조건, 획득처, 연출 미리보기를 읽는다.
- 하단에 레벨 바와 `다음: 레벨 23에 두 번째 선택 슬롯` 한 줄을 둔다. 남은 exp 숫자를
  카운트다운으로 압박하지 않는다.
- 선택 스킬 카드를 짧게 누르면 현재 주결·보조결 스킬과 보유 기록서 목록이 열린다.
  목록도 아이콘·이름·source·상성만 먼저 보여 주고 전문은 같은 상세 동작에서 연다.
  미보유 기록서는 획득 조건을 그대로 보여 준다.
  잠긴 항목을 흐리게 처리하되 구매 유도 배지를 붙이지 않는다.
- 수확 캐릭터는 `기록을 돌아보면 Lv24`처럼 회향으로 오르는 effective level과
  변하지 않는 외형 stage를 나란히 설명한다.
- 첫 `B1` 해금 시 `잎맥 지도`, `조용한 심호흡`, `첫 호흡` 세 장을 실제
  플레이 예시와 함께 비교하고 한 장을 무료로 고른다. 결정을 재촉하는 타이머는 없다.

### 13.2 파티 준비 화면

- 3인 각각의 4슬롯과 선택 프리셋을 한 줄로 보여 주고 `stack_group` 충돌을 미리
  경고한다.
- 캐릭터 초상 옆에 주결 glyph, 선택 스킬 아이콘에는 실제 `affinity_code`를 표시하고,
  현재 몬스터 약점·내성과 맞는 슬롯에 `↑/↓`를 붙인다. 설명문을 목록에 반복하지 않는다.
- 각 캐릭터 카드에 6.6의 역할 배지(주 1·부 최대 1)를 표시한다. 배지는 정보이지
  요구가 아니며, 빈 역할을 채우라는 경고·강조를 붙이지 않는다.
- 같은 기록서를 여러 캐릭터 프리셋에 저장할 수 있다는 점을 유지하되, 현재 3인 안에서
  중복되면 출발 버튼 위에서 막는다. 충돌한 두 캐릭터와 대체 가능한 보유 책을 함께
  보여 준다.
- 추천 정렬은 지금처럼 최근 선두 횟수가 적은 식물을 먼저 제안한다. 등급이나 레벨이
  높은 캐릭터를 위로 올리지 않는다.
- 자동 지휘 미리보기는 공개된 정보로 선택할 첫 행동과 이유를 한 줄로 보여 준다.
  수동보다 높은 숨은 보정도, 일부러 조건을 놓치는 패널티도 없다.

### 13.3 상점

- `기록서` 탭을 신설한다. 캐릭터·의상·꾸미기 탭과 섞지 않는다.
- 목록에는 아이콘·이름·가격·획득 상태만 두고 전문을 반복 노출하지 않는다. 길게 누르기·
  `상세 보기`와 구매 확인 sheet에서는 효과·장착 가능 슬롯·유효 상황을 구매 전에
  빠짐없이 공개한다. 상세를 열지 않은 상태에서 바로 결제하지 않는다.
- 성능 비교 문구(`가장 강한`, `필수`)를 쓰지 않는다. 효과를 그대로 적는다.
- 미보유 캐릭터의 T3 효과도 상점에서 미리 읽을 수 있다. 사기 전에 알 수 있어야 한다.
- 캐릭터 카드에는 현재·Lv25·Lv30의 고유 계수, 조건 미충족 저점, 예상 발동률 기준
  기대값, 조건 충족 고점을 함께 보여 준다. 가격이 높다는 이유만으로 `상위 등급`
  배지를 붙이지 않고 `안정형`·`순서 숙련형`처럼 조작 성격을 적는다. 6.6의 역할
  배지를 조작 성격과 나란히 표기한다(`돌봄 · 안정형`).
- 가격 인상 예고와 최근 하향·환불 가능 기간은 구매 버튼 바로 위에 표시한다.

### 13.4 수호전

- 전장 하단은 `기본·고유 I·고유 II·선택 I·선택 II·지키기` 6아이콘을 고정
  순서로 표시한다. `스킬` 목록 팝업이나 큰 설명 카드는 열지 않는다.
- 고유·감정·기록서 아이콘은 10.2.1의 ImageGen 도색 그림을 쓰고 선택 두 칸은 실제
  장착 source를 그대로 보여 준다. 비용은
  숫자와 원형 링, 남은 횟수는 잎눈, 잠금은 자물쇠와 한 단어 사유로 함께 표시한다.
- `opening|trigger` 책은 아이콘 자리를 유지하면서 `자동` glyph와 `대기|발동됨|소진`
  상태를 표시한다. 눌러도 행동으로 선택되지 않으며 발동 순간에는 해당 10F 모듈과
  원인 한 줄이 전장 안에서 재생된다.
- 짧게 탭하면 설명 노출 없이 선택/실행하고 길게 누르면 예상 장벽 피해, 집중력 비용,
  tier, 상성, 조건, 현재 적용된 선택 효과를 보여 주는 peek sheet가 열린다.
  `space=combat` 트리 node가 생기는 미래 버전만 node를 덧붙이며 v1.3 탐험 node는 표시하지 않는다.
- 조건이 꺼져 있으면 그 이유를 한 줄로 읽는다. 조건을 켤 방법도 함께 알려 준다.
- 아이콘을 길게 누르면 상세 설명을 띄우되 전투 화면을 전환하지 않는다. 손을 떼면
  원래 명령 화면으로 돌아온다.
- 아이콘 아래 스킬명·효과 한 줄, 탭 뒤 설명 카드, 화면 하단 순환 도움말은 모두 0개다.
  스킬 이름은 long-press 상세와 실제 시전 순간의 짧은 행동명에서만 보인다.
- AUTO 버튼은 다음 한 행동만 맡기는 `보조`와 전투 종료까지 맡기는 `연속`을 분리한다.
  언제든 명령 사이에 해제할 수 있고, AUTO가 고른 이유를 전투 로그에 남긴다.

### 13.5 스킬트리 배치

스킬트리는 전투 화면에 펼치지 않는다. 캐릭터 상세의 `스킬 · 트리 · 진화` 세 탭 중
`트리`가 소유하고, 전투 long-press에는 현재 적용 결과만 요약한다.

- 상단은 `고유 I 탐험 트리 | 고유 II 진화` 두 탭이다. **90노드 트리는 고유 I에만**
  적용되고 고유 II는 6.3의 고정 T1→T2→T3 진화·조건을 보여 준다. 아직 존재하지 않는
  고유 II 분기 트리를 UI만 그려 약속하지 않는다.
- 휴대폰의 탐험 트리는 품종별 세 갈래 selector를 두고 선택한 한 갈래의
  `뿌리 → 1단 → 2단 → 3단`을 위에서 아래로 보여 준다. 세 갈래 9노드를 한 화면에
  축소해 작은 노드 숲으로 만들지 않는다.
- 태블릿·가로 화면은 세 갈래를 좌우에 나란히 놓되 tier 행의 높이와 node 순서를
  동일하게 유지한다. 화면 크기에 따라 선행 관계가 바뀌지 않는다.
- 노드는 48dp 이상이고 아이콘+이름+한 줄 효과를 가진다. 연결선은 관계를 돕는 장식일
  뿐 탭 대상이 아니며, 핀치 줌·정밀 드래그를 필수 조작으로 만들지 않는다.
- 기본 뷰는 현재 보유 point와 다음 선택 행을 중심에 놓고 이미 지난 행은 접는다. `전체 보기`와
  스크린리더용 계층 목록은 같은 순서·같은 효과 전문을 제공한다.
- `B1·B2`는 트리 가지가 아니라 교체 장비다. 트리 아래에 섞지 않고 2×2 슬롯 보드의
  아래 두 칸에서 바꾼다. 사용자가 고유 진화와 스킬북 장착을 같은 강화로 오해하지
  않게 한다.
- node 선택·재배분은 run 밖에서 무료이고, 변경 전/후 행동 예시를 나란히 보여 준다.
  전투 중에는 편집할 수 없다. 탐험 현장 아이콘에는 적용 node 배지를 표시하지만 v1.3
  전투 S1·S2에는 node를 합성하거나 배지를 붙이지 않고 현재 tier와 T3 조건만 표시한다.

## 14. 밸런스 운영

### 14.1 지표와 경보선

하나의 전체 평균으로 패치하지 않는다. 모든 대시보드는 희귀도 1~5, 레벨
3~8·9~15·16~24·25~30, 해당 스킬 사용 1~3회·4~20회·21회 이상, 수동·AUTO,
`gentle`·`standard`·`deep`·`mastery`, 기록서 0·1·2권, 길잡이 0·1·2명을 분리한다.
신규·개편 스킬은 비긴급 변경 전 **14일 학습 기간**을 둔다.

재현 가능한 버그·보안·광과민 위험을 제외하면 대상 구간에 완료 전투 500회와 고유
사용자 200명이 모이기 전에는 수치를 바꾸지 않는다. 95% 신뢰구간이 경보선을 이틀
연속 벗어나야 조정 후보가 된다. 선택률은 발견성·취향 지표일 뿐 위력의 증거가 아니다.

| 지표 | 경보선 | 조치 |
|---|---:|---|
| 등급별 수호전 평균 라운드 편차 | 0.4라운드 초과 | 조건 문장·유효 장면 먼저 조정. 계수는 마지막 |

분석 event에는 난수화한 식물·사용자 키, content version, 위 구간, 선택, 판정 결과만
남긴다. **일기 본문, 감정명, 감정 점수, 자유 입력, 상담성 문장**은 보내지 않는다.

### 14.2 조정 우선순위

밸런스가 어긋났을 때 **아래 순서를 지킨다.** 인기 있는 것을 깎는 것이 가장 마지막이다.

1. 로그·리플레이·2,592환경/5,184명령 상태 시뮬레이션으로 문제를 재현한다.
2. 그 스킬이 쓸모없어 보이는 **사건·장면을 추가**한다.
3. **조건 문장과 적 예고**를 고쳐 발동률을 설계값으로 되돌린다.
4. 약한 쪽의 **적용 대상·타이밍**을 넓힌다.
5. 그래도 안 되면 **계수를 조정**한다.
6. 하향은 위 다섯 단계가 실패했고 5.6의 절대 상한을 실제로 넘었을 때만 한다.

어떤 캐릭터의 사용률이 높다는 이유만으로 그 캐릭터를 하향하지 않는다. 기존 탐험
설계서의 밸런스 운영 원칙을 이 문서에서도 그대로 유지한다.

### 14.3 하향 시 사용자 보호

- `nerf` 또는 `rework`는 긴급 악용 수정이 아니면 배포 **7일 전에 예고**하고, 전후
  수치·변경 이유·영향받는 조합을 함께 공개한다.
- 배포 후 **14일간** 해당 기록서를 구매 가격 기준 **씨앗 전액 환불**할 수 있다.
  환불하면 보유에서 빠지고
  장착 슬롯은 비워진다. 환불 창이 지나면 보유는 유지되고 환불만 닫힌다.
- 해금·던전 획득 기록서는 회수하지 않는다. 같은 가치의 선택권을 한 번 주고 기존
  기록서는 유지한다. 공지 시점에 보유하지 않은 같은 등급 활성 책을 후보로 고정하며,
  이미 같은 등급을 전부 보유했다면 선택권을 `대체 선택 불필요`로 완료 처리하고
  별도 재화나 중복 책을 만들지 않는다.
- 캐릭터 고유 스킬의 기대 기여가 5% 이상 낮아지거나 핵심 동작이 제거되면, 공지 전에
  보유한 사용자에게 해당 캐릭터의 **당시 해금 가격만큼 씨앗 credit을 한 번 지급**한다.
  캐릭터·레벨·일기 성장·숙련·의상은 그대로 남고 스킬트리와 프리셋을 무료로 재설정한다.
- 캐릭터·기록서 가격이 내려가면 기존 구매자에게 차액을 지급한다. 가격 인상은 기존
  보유자에게 소급 청구하지 않는다.
- 진행 중 run과 journey는 스냅샷을 유지한다. 시작한 판이 도중에 약해지지 않는다.
- 이미 얻은 3등급 기록서를 회수하지 않는다. `is_active=false`로 신규 획득만 닫는다.
- 보상은 `skill_balance_changes`와 사용자별 멱등 원장으로 한 번만 지급한다.

### 14.4 배포와 롤백

모든 balance pack은 시뮬레이션 → QA 환경 → 사용자 5% 24시간 → 25% 24시간 → 100%
순서로 올린다. 오류율, 승률 범위, 경제 원장, 프레임 시간 중 하나라도 경보선을 넘으면
자동 승격을 멈춘다. 마지막 검증 pack으로 15분 안에 되돌릴 수 있어야 하며, 서버
kill switch로 새 효과만 끄더라도 구버전 클라이언트는 공용 impact와 기존 수치로
계속 플레이할 수 있어야 한다.

### 14.5 패치 주기

| 주기 | 내용 |
|---|---|
| 6주 pack | 기록서 4종, 품종 1종 전용 진화 연출, 기존 지역 사건 4개, 밸런스 조정 |
| 2주 관찰 창 | 신규·개편 스킬은 비긴급 수치 변경 없이 학습 구간 데이터 수집 |
| 수시 hotfix | 재현 버그·악용·접근성·크래시만 수정하고 다음 정규 노트에 이력 포함 |
| 분기 리포트 | 지표 요약과 변경 이유를 사용자에게 공개. 개별 사용자 데이터는 포함하지 않음 |

새 지역을 추가할 때만 기록서를 추가하지 않는다. 기존 네 지역에도 같은 양의 새 사건과
새 기록서 유효 장면을 역류시켜, 초기 지역과 초기 캐릭터가 계속 현재 콘텐츠에 남게 한다.

## 15. 콘텐츠 validator

콘텐츠 팩 CI가 다음을 강제한다. 하나라도 실패하면 배포하지 않는다.

- 열 품종마다 고유 I·II family code가 정확히 하나씩 있고 현재 canonical code와
  일치한다. code에 `.1`·`.2`·`.3` tier 접미사가 없으며 tier는 별도 1~3 값이다.
- alias map은 순환·다단 체인·canonical 충돌이 0건이고 새 응답과 snapshot에 alias를
  쓰지 않는다.
- 모든 행동은 `slot/source → 기본|tier|선택 payload 중 하나 → 스킬트리 대체 또는
  선언된 auto hook → 희귀도 bp → 상성 → 조건 → 상한 → 단일 반올림` 순서를 따른다.
  S1/S2와 B1/B2 command를 한 행동으로 합성하거나 opening/trigger를 임의 시점에
  끼워 넣을 수 없다.
- 기존 90노드의 `space`는 전부 `expedition`이며 S1 전투 payload 계산에서 읽힌 node가
  0건이다. combat node가 없는 상태에서 node code를 전투 요청으로 보내면 422다.
- 모든 기록서가 닫힌 `effect_module` 하나, 단일 `stack_group`, `effect_budget` 1~2를
  가진다. 두 효과를 한 책에 넣은 항목이 0건이다.

## 16. 테스트 계약

### 16.1 서버 unit / property

- `base_level_from_exp`가 30레벨 exp 경계의 직전·정확값·직후에서 표와 일치한다.
- active의 effective level은 base와 같고, harvested는 회향만 합산하며 30에서 멈춘다.
  회향이 stage·final form·감정 프로필을 바꾸지 않는 property를 전수 검사한다.
- `FORM_STAT_MODIFIERS` 합이 여섯 성장형 모두 4다. 기존 불변식 테스트 유지.
- `maturity` 적용 후에도 `effective_stat <= 지역 상한`이 모든 stage·레벨·성장형·
  지역 조합에서 성립한다.
- 다섯 등급 × 30레벨 `rarity_scale_bp`가 부록 C fixture와 일치하고 최종 행동에서만
  round-half-up을 한 번 적용한다.
- 현재 고유 I·II canonical code 20개가 보존되고 tier를 올려도 code가 바뀌지 않는다.
  alias 정규화 결과와 composition 순서가 모든 효과 모듈에서 동일하다.
- 고유 I 전투 payload 10종이 P·집중력·charge·T2·T3 표와 일치하고, charge는 웨이브
  전환에 회복되지 않으며 같은 멱등 요청 재생에서 두 번 차감되지 않는다.
- 감정 스킬 6종의 P·후속 효과·집중력·charge가 6.8과 일치하고, `emotion.primary|secondary`
  포인터가 run 시작에서 한 번만 실제 family로 resolve된다.
- 20개 원소가 여섯 성장결로 빠짐없이 매핑되고, 약점은 최종 장벽 피해 `×1.50`, 내성은
  `×0.60`과 최소 1, 중립은 `×1.00`을 적용한다. 이 값이 회복·방어·집중력에 섞이거나
  약점과 내성이 한 행동에 동시에 적용되는 경우가 0건이다.
- 5,184명령 상태 가중 평균에서 같은 레벨 T3의 기여가 T2보다 낮지 않다.
- 같은 레벨에서 **실제 기여**의 평균·P95가 1.25·1.35 이하다. 기본 power,
  회복·방어·집중력·감정 상성·조건·고유 I charge까지 포함한 5,184명령 상태 전수 계산이다.
- 기록서를 포함한 3인 파티 최대 조합이 미장착 동일 파티의 1.60배를 넘지 않는다.
  `ringcount_record` × `shadow_oath` × 1등급 정액 보너스까지 함께 계산한다.
- 등급별 기대 위력 차가 10% 이하다.
- mastery level을 0→5로 바꿔도 어떤 판정·보상 수치도 달라지지 않는다.
- 기록서 module·등급·슬롯·stack group·반대급부 schema를 생성 기반 property test로
  검증한다.
- activation mode 20종의 command 비용·opening 순서·trigger 조건을 전수 검사하고
  opening/trigger가 대원 행동 수를 차감하지 않는 property를 고정한다.

### 16.2 서버 integration

- starter 세 후보 중 하나만 선택되고 같은 `client_action_id` 재시도는 같은 응답을
  돌려준다. 서로 다른 동시 요청은 한 건만 성공하며 씨앗을 차감하지 않는다.
- 구매·도전·해금·starter 네 획득 경로가 중복 보유를 만들지 않는다. 중복 구매와
  네트워크 재시도에서 씨앗 원장이 한 번만 기록된다.
- 같은 책을 여러 식물·프리셋에 저장할 수 있지만 실제 파티 중복은 출발 전에 422다.
  같은 감정 family의 선택은 허용한다. revision 충돌은 마지막 쓰기 덮어쓰기 없이 409다.
- 주간 일기 3일이 회향 권리를 한 번만 만들고, 성공·실패·동시 적용 모두 권리와
  `reflection_levels`를 원자적으로 보존한다.
- snapshot v1·v2·v3 run은 어댑터로 끝까지 진행되고 v4 run은 content version,
  프리셋, 감정 profile, 밸런스 pack을 바꿔도 시작 시 계산 결과를 유지한다. v2 진행 중
  run에는 S1 전투 payload를, v3 run에는 감정 선택 스킬·내성을 소급 주입하지 않는다.
- v4의 `emotion.primary|secondary` 포인터는 `selected_skills_snapshot`에 resolved code와
  affinity로 고정된다. 진행 중 주결·보조결 변경이나 수확이 이를 다시 해석하지 않는다.
- `skill_slot`과 `skill_code`가 snapshot과 다르면 422이며, 정상 S1 명령은 판정·charge
  차감·숙련 증가·교환 로그가 한 트랜잭션으로 한 번만 기록된다.
- opening 2권 동시 장착과 같은 event의 trigger 2권 발동을 재시도해도 B1→B2·파티
  순서가 결정적이고 각 charge·효과가 한 번만 기록된다.
- 대백과 replacement pool은 시작 뒤 구매·환불에 변하지 않고 파티 중복·stack
  conflict 후보를 내놓지 않는다.
- 구버전 던전과 새 직접 탐험을 같은 날 완료해도 XP·씨앗 reward lane은 한 번만 열린다.
- 기록서 전액 환불은 실제 구매 원장 금액을 쓰고, 캐릭터 seed credit과 가격 인하
  차액은 각각 대상 계정에 한 번만 지급된다. 보유·장착·잔액 변경은 한 트랜잭션이다.
- 5%→25%→100% pack 승격과 kill switch 롤백을 가짜 시계로 검증한다. 롤백 뒤 새 run은
  이전 pack, 진행 중 run은 자기 snapshot을 쓴다.
- 분석 이벤트 payload에 일기 본문·감정명·감정 점수 필드가 들어가면 테스트가 실패한다.
- 숨은 기록 5종은 획득 전 API JSON·접근성 label·분석 event에 이름·효과·정확 조건이
  없고 지역 hint만 있다. 획득 원장과 같은 트랜잭션 뒤에는 정확 정보가 열리며 재시도·
  기기 변경에서도 다시 잠기지 않는다.

- 기록서에 XP·씨앗 배율을 붙여 "체감"을 만드는 것
- 확률형 기록서 상자, 중복 지급 후 합성, 강화 실패
- 같은 기록서를 다른 캐릭터 프리셋에 저장하지 못하게 전역 장착 잠금을 거는 것
- 모든 난이도의 승률을 90%로 맞춰 선택 도전의 실패 가능성을 없애는 것
- 인기 캐릭터를 사용률만 보고 하향하는 것
- 3등급 기록서를 나중에 상점에서 판매하는 것
- 진화·조건 발동을 숨은 확률로 처리하는 것
- 비싼 캐릭터·특정 기록서를 필수 경로, 주간 재화, 독점 성장 재료의 입장권으로 쓰는 것
- 새 지역에서만 기록서를 공급해 초기 지역을 유물로 만드는 것
- 진화 연출을 등급별로 길게 만들어 5등급을 화려함으로 광고하는 것
- 생성 원본을 배경 제거·선 정리·pivot QA 없이 런타임 에셋으로 넣는 것
- 다른 게임의 캐릭터·스킬명·실루엣·UI·음원을 그대로 모사하는 것
- 밸런스 하향 때문에 캐릭터를 삭제하거나 레벨·일기 성장·숙련을 되돌리는 것
- 진행 중 run에 새 balance pack을 덮어쓰는 것
- 구버전 던전과 새 직접 탐험 보상을 같은 날 이중 지급하는 것
- 슬롯 해금을 씨앗이나 유료 상품으로 앞당기는 것

## 부록 A. 기준 성장 시나리오

### A.1 1일차 — 무료 스타터 뽀또

50자 마음 일기로 첫 감정 10 + 일기 30 = exp 40, 씨앗 15를 받는다. 레벨 4,
stage 2 새싹이다. 탐험이 열리고 고유 I `새싹 응원`과 고유 II `포근한 싸개잎`을
T1으로 쓴다. 선택 슬롯은 잠겨 있고 카드는 `줄기가 되면 선택 스킬 한 칸이 열려요`라고
읽는다. 기억서고에서는 길잡이 둘과 `gentle` 수호전을 배운다.

### A.2 첫 주의 세 번째 기록일 — 첫 감정 스킬과 기록서

50자 일기와 일일 미션을 같은 날 끝내 하루 상한 50을 세 번 채우면 exp 150,
레벨 11·stage 3 줄기다. 안정 주결의 `emotion.primary`가 열리고 레벨 9에서 열린
`B1`에 바로 장착할 수 있다. 동시에 `잎맥 지도`, `조용한 심호흡`, `첫 호흡` 중
한 장을 무료로 골라 같은 선택 칸에서 언제든 교체한다. 세 기록일의 일기·미션 씨앗 60과 첫 주 순찰
21을 모두 받았다면 씨앗 81이므로 1등급 한 장(40)을 추가로 살 수 있다. 같은 책을
다른 캐릭터 프리셋에도 저장할 수 있지만 이번 파티에서는 한 번만 쓴다.

### A.3 2~3주차의 다섯 번째 충실한 기록일 — 첫 진화

하루 상한을 다섯 번 채워 exp 250이 되면 레벨 16, stage 4 개화다. 홈에서 진화
연출이 재생되고 `새싹 응원`이
`잎우산`이 된다. 이제 친구의 준비도 손실도 막을 수 있다. 수호전 고유 II에 자신
방어 +1이 붙는다. 14% 이상인 보조결이 있으면 `emotion.secondary`도 배우지만 두 번째
선택 칸이 열리기 전까지는 주결·보조결·기록서 중 하나를 B1에서 고른다. 씨앗 120을 모아 그림싹을 선택했다면 새 그림싹은 Lv3에서 무료
뽀또보다 저점이 낮고, Lv25 이후 직접 약점을 맞출 때 고점이 커진다는 설명을 상점에서
미리 확인한다. 비싼 캐릭터가 즉시 완성품을 주지는 않는다.

### A.4 아홉 번째 상한 기록일 — 만개와 두 번째 슬롯

exp 450에서 레벨 23, stage 5 만개가 되고 `B2`가 열린다. 기억서고 깊은 조사를 처음 완주해
3등급 `뿌리 사서의 색인`을 얻고 `B2`에 끼운다. 지도 전체 노드 종류가 보이는 대신 숨은
간선은 스스로 찾아야 한다. 수확할 수도 있지만 레벨 30까지 키우기로 한다. 두 선택 모두
씨앗·XP 차이가 없다.

### A.5 T3와 레벨 30 — 활성·수확 두 경로

만개 뒤 하루 상한을 두 번 더 채워 exp 550이 되면 레벨 25와 T3가 열린다. 활성
캐릭터는 총 18번의 상한 기록일 또는 23번의 50자 일기만으로 exp 900, Lv30에
도달한다. Lv23에 수확했다면 주간 일기 3일로 얻는 회향을 7번 적용해 같은 전투
Lv30에 천천히 도달하며 외형·감정 성장형은 수확 당시 그대로다.

Lv30에서 수호전 HP는 6이고 파티 평균 조건을 충족하면 시작 집중력이 4다. 등급 1 뽀또의
위력 계수는 1.20이다. 같은 레벨의 5등급 설화는 1.32이고 조건을 맞추면 1.50이지만,
조건을 놓치면 1.13으로 뽀또보다 낮다. 파티 평균 성장지수 100에서 장벽은 최대 30%
두꺼워진다. K4 전수 결과는 일반 2웨이브 P50 3라운드, 큰 엉킴 P50 2라운드,
혼합 숙련 P50 3라운드다. 튜토리얼의 1라운드 완료만 허용하고 나머지 형태는 0건이다.

## 부록 C. 계산 fixture와 단일 원본

### C.1 고정 상수

| 항목 | 값 | 단일 원본 |
|---|---|---|
| stage exp | `0, 20, 100, 250, 450` | 기존 `stage_from_exp` |
| 30레벨 exp | 3.2 표의 30개 누적값 | `character_skill_growth_v1.json` |
| 일일 XP 상한 | 50 | 기존 XP 원장 |
| 희귀도 base | `1.00, 0.98, 0.96, 0.94, 0.92` | 같은 content fixture |
| 희귀도 slope | `0.20, 0.25, 0.30, 0.35, 0.40` | 같은 content fixture |
| 기록서 가격 | 1등급 40, 상점 2등급 120 | 상점 catalog |
| 수호자 성장 장벽 | `1.00..1.18` | 9.1 |
| 반올림 | 양수 round-half-up, 최종 행동 1회 | 서버 도메인 함수 |

`character_skill_growth_v1.json`은 구현 시
`server/app/content/character_skill_growth_v1.json`에 두고 서버·validator·문서 표
생성기가 함께 읽는다. 문서에 적힌 숫자를 앱에 다시 손으로 옮기지 않는다.

### C.2 정수 계산

```text
full_rarity_bp = rarity_scale_bp(effective_level, rarity)
action_scale_bp = basic_rarity_bp(full_rarity_bp) for basic|S1
                | full_rarity_bp for S2
                | 10_000 for unscaled emotion|book selected-skill values
condition_bp = 10_000 | tier_condition_bp
scalable_raw = tier_base_after_tree_replacement
fixed_delta = unscaled_selected_skill_delta

scaled = (
  scalable_raw * action_scale_bp * condition_bp + 50_000_000
) // 100_000_000

final_value = clamp(scaled + fixed_delta, action_floor, action_cap)
```

중간 단계에서 반올림하지 않는다. 피해·방어·회복처럼 단위가 다른 값은 각각 독립
`scalable_raw`를 가지며 서로 합산해 가짜 "총 power"를 만들지 않는다. UI 미리보기,
전투 판정, 리플레이는 같은 `calculation_trace` fixture를 읽는다.

필수 golden은 다음 여덟 묶음이다.

1. 30레벨 × 5등급 bp 150개
2. 현재 고유 스킬 T1 code·power·focus cost 20개
3. 10품종 × T1/T2/T3 × 조건 on/off 계산
4. 2,592환경/5,184명령 상태 실제 기여 결과
5. 9.1의 세 파티 장벽·순 우위
6. 8.2의 1일·1주 경제 원장과 구·신 보상 lane 충돌
7. 감정 스킬 6종의 P·후속 효과·charge와 primary/secondary pointer resolve
8. 일반 엉킴 12종의 고정 약점·내성 및 여섯 결별 2회/2회 분포

### C.3 계약 충돌 우선순위

구현 중 문장과 fixture가 충돌하면 `기존 불변식(1장) → 절대 상한(5.6) → 계산
fixture → 카탈로그 문장 → UI 표현` 순서로 판정한다. 수치를 바꾸려면 content version,
시뮬레이션 결과, 사용자 보호안을 한 변경 묶음으로 리뷰한다. 이 순서를 무시하는
캐릭터별 상수·프레임별 예외는 허용하지 않는다.
