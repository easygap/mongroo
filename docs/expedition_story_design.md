이 문서는 흩어져 있던 서사 요소 — 지역 정체성, 수호자, `run_thread`, 관계 beat,
캐릭터 lore, 온실 밖 개척 — 를 **하나의 세계관과 하나의 원고 계약**으로 묶는다.
구조와 수량은 기존 문서를 그대로 승계하고, 이 문서는 그 안에 들어갈 **실제 이야기의
단일 원본**이다. 여기 없는 설정을 구현 편의로 만들지 않고, 여기 적힌 원고를 임의로
바꾸지 않는다.

## 문서 적용 전제

몽그루의 본편은 마음 일기다. 스토리는 일기를 쓰는 이유가 아니라 **일기를 쓰고 난
자리에 놓인 세계**다. 다음 다섯 줄은 이 문서의 모든 원고보다 우선한다.

1. 스토리는 어떤 채널에서도 XP·씨앗·수집품·가치 예산을 지급하거나 바꾸지 않는다.
2. 사용자의 일기 본문·감정명·감정 점수·자유 입력은 스토리의 입력 변수가 아니다.
3. 스토리는 사용자를 진단·해석·위로하는 역할을 맡지 않는다. 캐릭터의 세계를 산다.
4. 모든 이야기는 건너뛸 수 있고, 놓친 이야기는 언제든 같은 조건으로 다시 만난다.
5. 마음정원에서는 아무도 죽지 않고, 잃어버린 것은 잊힐 뿐 사라지지 않는다.

### 0.1 2026-08-18 구현 스냅샷

- 네 지역에 `run_thread` 3종씩 총 12종·84문장을 콘텐츠 팩으로 실었다. 지도
  템플릿이 seed/echo 변형을 결정하고, 실제 런에서 가장 많이 쓴 접근 계열이
  careful/bold/relational payoff를 결정한다.
- 최근 다섯 노출에서 보지 않은 thread를 먼저 고르고, 세 종을 모두 본 경우 가장
  오래전에 본 thread부터 되돌린다.
- 현재 플레이 가능 15품종 전부에 departure/camp/return 전용 원고를 두었다.
  동종을 포함한 120개 조합 × 3시점 = 360개 관계 장면을 런타임 LLM 없이
  결정적으로 구성하며, 출발 화면·쉼터·귀환 요약에 실제 노출한다.
- 서로 다른 15품종의 `15×14÷2 = 105`조합에는 야영지 핵심 대화 4줄과
  회상 대화 2줄을 각각 두었다. 계정에서 처음 만난 조합은 core, 다음 만남부터는
  reprise를 노출하며 서버 노출 원장이 반복 여부를 결정한다. 장거리 개척 전용
  화면이 추가되기 전에도 현재 플레이 가능한 쉼터에서 이 원고를 만날 수 있다.
- 위 수량과 모든 품종 커버리지는 서버 단위·통합 테스트에서 출시 관문으로 고정한다.

## 1. 세계관 — 마음정원 한 장

### 1.1 전제

몽그루의 화분 친구들은 커다란 온실 `마음정원`에서 산다. 정원은 아주 오래전부터
있었고, 화분들이 오기 전의 시간은 네 개의 방 — 기억서고, 우물정원, 씨앗 보관고,
마음나무 관측실 — 에 남아 있다. 사용자가 일기를 쓰면 정원에 새 숨이 돌고 탐험길이
열리지만, **정원의 사건들은 사용자의 마음을 재현한 것이 아니다.** 정원은 캐릭터들의
세계이고, 사용자는 그 세계를 돌보는 손님이자 기록자다.

이 전제가 지키는 것은 안전이다. 지역과 사건이 사용자 감정의 은유가 되는 순간,
탐험 실패는 "내 마음이 실패했다"로 읽힌다. 몽그루의 탐험은 언제나 **캐릭터들의
이야기**이므로, 사용자는 부담 없이 구경하고 웃고 되돌아올 수 있다.

### 1.2 세계의 여섯 규칙

1. **나쁜 감정은 없다.** 몽그루의 대전제이며 이 세계관의 제1 규칙이다. 여섯 감정
   성장형과 여섯 공명 어디에도 악역·오염·저주가 없다. 어떤 사건·지역·캐릭터도
   특정 감정을 문제, 적, 극복 대상으로 그리지 않는다. 수호짐승의 완고함도 나쁜
   마음이 아니라 지키려는 마음이 너무 커진 것이다. 이 세계의 갈등은 감정끼리의
   싸움이 아니라 **잊힘·엇갈림·기다림**에서 나온다.
2. **아무도 죽지 않는다.** 위험은 막힌 덩굴, 잠긴 문, 멈춘 장치, 길 잃은 소리다.
   죽음·소멸·붕괴·처치는 사용자 노출 문구 어디에도 쓰지 않는다.
3. **잃어버린 것은 잊힌 것이다.** 부서져 없어진 물건은 없다. 모든 분실물은 서고의
   어느 서랍, 우물의 어느 바닥에서 언젠가 다시 찾을 수 있다.
4. **문은 잠긴 것이 아니라 기다린다.** 진행을 막는 장애물은 파괴 대상이 아니라
   아직 조건을 못 갖춘 약속이다. 열리는 날은 콘텐츠 추가로만 오고, 확률·과금·기간
   한정 뒤에 두지 않는다.
5. **시간은 세 방향으로 흐른다.** 서고는 지난 것을, 보관고는 아직인 것을, 우물정원은
   지금 오가는 것을 맡는다. 관측실은 셋을 한 장에 잇는다. 새 지역도 이 축 위에서
   자기 시간을 갖는다.
6. **온실 밖은 위협이 아니라 초대다.** 바깥에서 오는 모든 신호(우편, 필체, 이름)는
   호기심의 대상이지 공포의 대상이 아니다.

### 1.3 용어 canonical 표

사용자 노출 문구는 아래 왼쪽 열만 쓴다. 오른쪽 표현이 코드 주석·내부 문서에 남는
것은 허용하지만 화면·스토어 문구·알림에서는 금지다.

| canonical | 금지 표현 |
|---|---|
| 마음정원 | 월드, 맵 |
| 직접 탐험 | 던전 공략, 파밍 |
| 수호자 / 관리인 / 수호짐승 | 보스, 몬스터, 몹, 적 |
| 수호 장벽을 연다 / 길을 내어 준다 | 처치한다, 쓰러뜨린다, 킬 |
| 긴급 귀환 / 안전 귀환 | 패배, 전멸, 게임 오버 |
| 우회한다 (`detour`) | 실패한다, 도망친다 |
| 마음결 기록서 | 스킬북, 장비 파밍 |
| 정원 길잡이 | 용병, NPC 캐릭터 |

## 2. 스토리 안전 규칙

`docs/safety.md`와 기존 탐험 문서의 안전 계약을 서사에 그대로 적용한다.

- 일기 본문·감정명·감정 점수·자유 입력·상담성 문장은 스토리 변수·조건·문구 치환에
  쓰지 않는다. 선택 기억(`approach` 등)은 **플레이 행동으로만** 계산한다.
- 스토리 문장은 사용자의 상태를 단정하지 않는다. `오늘 힘들었으니`, `당신의 슬픔처럼`
  같은 되받아 말하기가 한 문장이라도 발견되면 출시 차단이다.
- 위기 지원이 활성화된 날에는 새 thread·새 회상을 노출하지 않는다. 이미 발견한
  도감·기록의 열람은 언제나 허용한다.
- 이별 소재는 `잠시 헤어짐`과 `다시 만남`의 구조로만 쓴다. 상실을 미화하거나
  극복 서사를 강요하지 않는다.
- 무서움은 어둠 속 낯선 소리 수준까지만 쓰고, 정체가 밝혀지면 반드시 무해하거나
  다정한 것이어야 한다. 공포의 대상이 공포로 남은 채 끝나는 사건은 만들지 않는다.
- 수호짐승은 무섭게 그리지 않는다. 몸집이 크고 완고할 뿐, 표정과 사후 연출은
  언제나 지키려던 것을 드러낸다.

## 3. 스토리 전달 채널 지도

스토리는 한 화면에 몰아 나오지 않고 아래 채널에 나눠 흐른다. 각 채널의 수량과
규칙은 원 문서를 따르고, **어떤 채널에 어떤 이야기를 넣는가**를 이 표가 정한다.

| 채널 | 위치 | 출시 수량 | 맡는 이야기 | 하지 않는 것 |
|---|---|---:|---|---|
| `run_thread` | 일반 run의 seed/echo/payoff | 12종 84문장 | 한 판을 한 편의 모험으로 잇는 뼈대 | 보상 지급, 필수 경로 차단 |
| 일반 사건 40종 | 지도 사건 | 기존 승계 | thread 사이의 호흡과 지역 장치 | thread 없이는 이해 불가한 전개 |
| 발견 장면·도감 | discovery, 도감 32종 | 기존 24 + 신규 8 | 세계의 조각, 미해결 질문의 물증 | 완료 보상, 수집 강요 |
| 관리인 사건 | 수호자 단계 사건 | 4명 11단계 | 지역의 중심 인물과 협력 | 전투, 성능 보상 |
| 수호전 | 수호짐승 장벽 | 4마리 | 지키려는 마음과 길을 내어 주는 순간 | 처치·죽음 표현 |
| 깊은 꿈(합동 수호전) | 6인 협동 전투 | 짐승 4 × 꿈 장면 4 | 짐승을 함께 깨워 주는 큰 이야기, 부름말의 무대 | 경제 보상, 랭킹 |
| 관계 beat | 출발·쉼터·귀환 | 360 | 파티 두 명 사이의 짧은 순간 | 성능·보상 언급 |
| 야영지 짝 대화 | 쉼터·향후 개척 야영지 | core 105 + reprise 105 | 평소 못 보는 조합의 핵심 장면 | 같은 core 반복 지급 |
| 유대 기록 | 캐릭터 상세·홈 | 4단계 | 나와 캐릭터가 함께 걸은 시간 | 전투력·보상 연동 |
| 귀환 회상 | 홈 첫 진입 | run당 1문장 | 여운. 장소·상대·선택 중 하나 | 자동 반복 재생 |
| 표본 연구 | 연구 완성 카드 | 기존 승계 | 수집품이 어디서 온 무엇인지 | 연구 효과 수치 서사화 |
| 진화 안내 문구 | 홈 진화 연출 | 40종 | 스킬 이름이 자라는 개인 서사 | 수치·성능 자랑 |
| 도감 lore | `lore_hook` 등 | 기존 승계 | 캐릭터 첫 소개 | 위로·해석 문구 |

채널 공통 규칙 세 줄.

- 같은 이야기 조각은 자동으로는 한 번만 재생하고, 이후에는 개인 기록에서 다시 본다.
- 한 화면에 동시에 나오는 스토리 문장은 최대 1개다. 스토리가 판정 정보를 가리면 안 된다.
- 스토리를 읽지 않고 전부 건너뛴 사용자도 진행·보상·밸런스에서 아무 차이가 없다.

## 4. 네 지역의 서사

지역의 플레이 정체성(핵심 동사·능력치·장치)은 탐험 설계서 8장을 따른다. 이 장은
각 지역이 **어떤 질문을 품고 있는가**를 정한다. 지역의 모든 thread·사건·발견
장면은 자기 지역의 질문을 벗어나지 않는다.

### 4.1 이끼 낀 기억서고 — 지난 것들의 방

- 질문: **잊힌 기억은 어디로 가는가.**
- 서고는 정원이 겪은 모든 날을 표본과 장부로 보관한다. 버려진 기억은 없고, 분류를
  기다리는 기억만 있다. 뒤집힌 서랍·숨 쉬는 장부는 고장이 아니라 오래된 기억이
  자기 자리를 찾는 소리다.
- 관리인 뿌리 사서는 이 방을 혼자 너무 오래 지켰다. 첫 완주가 사용자에게 가르치는
  탐험 조작처럼, 서고의 이야기는 사서가 "정리를 나눠 맡기는 법"을 배우는 과정이다.
- 발견 장면의 서사 위치: `뒤집힌 표본 서랍`(찾던 흔적) → `뿌리로 잠긴 문`(아직
  기다리는 약속) → `숨을 쉬는 장부`(방 자체가 살아 있음) → `vein_index` 잎맥
  색인(사서가 잃어버린 도구) → `greenhouse_postcard` 말라붙은 온실 우편(바깥에서 온
  첫 신호, 10장의 아크 시작점).
- 다음 지역으로 넘기는 고리: 장부에 적힌 소리 기록이 우물정원의 메아리를 가리킨다.

### 4.2 메아리 우물정원 — 돌아오는 대답의 방

- 질문: **대답 없는 부름은 실패인가.**
- 우물정원의 모든 소리는 언젠가 돌아온다. 늦게 돌아오는 대답, 반 음 낮게 돌아오는
  대답, 아직 길을 못 찾은 대답이 있을 뿐이다. 사용자가 소리 장치를 되돌려주는
  플레이는 그대로 "대답을 데려다주는" 이야기가 된다.
- 관리인 물결 종지기는 모든 음이 제 짝을 찾을 때까지 종을 걸어 두는 인물이다.
  종지기의 기보에는 빈칸이 있고, 그 빈칸이 이 지역 thread의 심장이다.
- 발견 장면의 서사 위치: `돌아온 작은 속삭임` → `물 아래의 종`(기다리는 대답) →
  `소리로 놓인 계단`(대답이 만드는 길) → `twice_returned_name` 두 번 돌아온
  이름(낯선 화음, 미해결 질문) → `under_ripple_garden` 물결 아래 작은 정원(소리가
  가꾼 또 하나의 정원).
- 다음 고리: 물길이 나르는 별빛 알갱이가 보관고의 선반에서 발견된다.

### 4.3 별빛 씨앗 보관고 — 아직의 방

- 질문: **미래는 언제 심어야 하는가.**
- 보관고의 씨앗은 늦은 것이 아니라 아직인 것이다. 멈춘 발아 시계, 절반에서 멈춘
  모래시계는 전부 "그 씨앗의 때"를 기다리는 장치다. 빛을 정렬하는 플레이는 각
  씨앗에게 맞는 아침을 찾아 주는 이야기다.
- 관리인 발아 시계지기는 서두르지 않는 것과 미루는 것 사이에서 매일 저울질한다.
  시계지기의 태엽 소리가 느려질 때는 어딘가의 씨앗이 아직 준비되지 않은 때다.
- 발견 장면의 서사 위치: `거꾸로 선 씨앗함` → `멈춘 발아 시계` → `별자리를 닮은
  새싹`(하늘과 씨앗의 연결) → `bottled_dawn` 새벽을 보관한 병(첫 발아의 기념,
  개척 출발 연출의 유래) → `roots_of_light` 빛의 뿌리(빛이 아래에서도 온다는 발견).
- 다음 고리: 빛의 뿌리 지도가 관측실의 표본 태그 장치와 같은 문양을 쓴다.

### 4.4 마음나무 관측실 — 함께 잇는 방

- 질문: **혼자 쓴 기록과 함께 쓴 기록은 무엇이 다른가.**
- 관측실은 앞선 세 방의 시간을 한 장의 기록으로 잇는다. 비어 있는 나이테는
  기록할 손이 하나뿐이던 해의 흔적이고, 파티 셋이 기록을 한 장으로 묶는 수호자
  사건은 이 지역의 질문에 대한 플레이 그 자체다.
- 관리인 나이테 관측자는 네 관리인 중 가장 오래 혼자였다. 관측자의 서사는 "기록은
  함께 쓰면 비지 않는다"를 배우는 과정이며, 온실 밖 첫 지도를 내어 주는 인물이다.
- 발견 장면의 서사 위치: `비어 있는 나이테` → `뿌리 아래 보관함` → `온실 밖 첫
  지도` → `shared_margin` 함께 그린 여백(두 번째 필체, 미해결 질문) →
  `second_greenhouse_door` 두 번째 온실의 문(아크의 문).
- 다음 고리: 지도의 끝, 손잡이가 바깥쪽에 달린 문. 10장의 장기 아크로 이어진다.

### 4.5 지역 서사 공통 규칙

- 지역의 질문에는 정답이 없다. payoff는 접근 방식에 따라 서로 다른 **좋은 결말**을
  주고, 어느 결말도 다른 결말을 정답으로 만들지 않는다.
- 발견 장면 32종은 전부 어느 thread 또는 미해결 질문의 물증과 연결된다. 어디에도
  연결되지 않은 외딴 발견을 새로 만들지 않는다.
- 새 지역을 추가할 때는 1.2의 시간 축 위에서 그 지역의 질문 한 줄을 먼저 확정하고,
  질문 없는 지역을 만들지 않는다.

## 5. 수호자 — 관리인 4명과 수호짐승 4마리

### 5.1 이중 구조를 명문화한다

기존 문서와 구현 사이에 이름 층위가 두 개 존재한다. 탐험 설계서 8.7의 수호자
단계(뿌리 사서 등, 다단계 협력 사건)와, 구현된 수호전의 `ledger_keeper` 돌비늘
장부지기(장벽 전투)다. 이 문서는 둘을 다음 구조로 확정한다.

- **관리인**: 지역을 돌보는 인물. 8.7의 다단계 사건에서 파티와 협력하고, 서사
  대화를 가진다. 전투하지 않는다.
- **수호짐승**: 관리인이 오래 데리고 지낸 커다란 동반자. 맡은 것을 지나치게 꼭
  끌어안는 습성 때문에 길을 막고, 수호전에서 장벽을 연다. 대사는 없고 몸짓과
  울음으로만 말한다.
- 수호전에서 장벽을 여는 것은 짐승을 해치는 것이 아니라 **품을 열어 보여 주게
  하는 것**이다. `수호자를 죽이는 표현 대신 수호 장벽을 0으로 만든다`는 수동 지휘
  계약 4의 규칙이 이 서사의 근거다.

| 지역 | 관리인 | 수호짐승 code | 수호짐승 이름 | 끌어안고 있는 것 |
|---|---|---|---|---|
| 기억서고 | 뿌리 사서 | `ledger_keeper` | 돌비늘 장부지기 | 아직 분류하지 못한 기억 장부 |
| 우물정원 | 물결 종지기 | `echo_keeper` | 물거울 메아리지기 | 주인을 못 찾은 메아리들 |
| 보관고 | 발아 시계지기 | `seed_keeper` | 별가루 씨앗지기 | 때가 안 된 씨앗함 |
| 관측실 | 나이테 관측자 | `ring_keeper` | 옹이등 기록지기 | 완성 못 한 관측 기록 한 장 |

`ledger_keeper`와 그 스킬 `ledger_claw`는 구현 code를 그대로 승계한다. 신규 세
마리 code는 위 표로 고정하며, 지역 콘텐츠 팩이 이 code를 사용한다.

### 5.2 관리인 4명의 서사

| 관리인 | 한 줄 정체 | 결핍 | 파티가 주는 것 | 연결된 3등급 기록서 |
|---|---|---|---|---|
| 뿌리 사서 | 정원의 모든 날을 분류하는 사서 | 혼자 다 하려다 색인을 잃어버림 | 정리를 나눠 맡아도 된다는 경험 | `librarian_index` 뿌리 사서의 색인 |
| 물결 종지기 | 모든 음의 짝을 찾아 주는 조율사 | 기보의 빈칸, 대답 못 받은 음 | 함께 불러 주는 화음 | `bellringer_chime` 물결 종지기의 종 |
| 발아 시계지기 | 씨앗마다의 때를 지키는 시계공 | 기다림과 미룸을 구분 못 하는 날 | "함께 기다리기"라는 선택지 | `germination_gear` 발아 시계의 태엽 |
| 나이테 관측자 | 마음나무의 해를 기록하는 관측자 | 기록할 손이 하나뿐이던 해 | 여백을 같이 쓰는 손 | `ringcount_record` 나이테 관측 기록 |

- 3등급 기록서 4종은 깊은 조사 최초 완주 보상이며, 서사상 **관리인이 자기 도구를
  파티에 맡기는 장면**이다. 획득 연출 900ms 안에 관리인의 한 문장을 포함한다.
- 관리인 대화는 첫 만남(사건 안 원고)과 재방문 대사 3종씩을 가진다. 재방문 대사는
  최초 완주 뒤, 깊은 조사 완주 뒤, 해당 지역 thread 3종을 모두 본 뒤에 하나씩
  열린다. 수량은 4명 × 3종 = 12문장이다.
- 관리인은 사용자를 위로하지 않는다. 자기 일과 자기 결핍을 말하고, 파티의 행동에
  구체적으로 반응한다.

### 5.3 수호전 서사 계약

- 수호전 진입 문구는 짐승이 **무엇을 지키는지**를 먼저 보여 준다. `돌비늘
  장부지기가 기억 장부를 꼭 끌어안고 길을 막아요`가 기준 문형이다.
- 승리 문구는 승패 언어를 쓰지 않는다. `장벽이 열리고, 장부지기가 품을 내어
  줬어요` 방향으로 쓴다. 긴급 귀환 문구는 `오늘은 여기까지. 장부지기는 내일도 같은
  자리에 있어요`처럼 재도전이 안전함을 알린다.
- 장벽이 열린 뒤 수호짐승은 사라지지 않고 그 지역의 배경에 남아, 재방문 시 잠든
  모습이나 관리인 곁의 모습으로 등장한다. 같은 짐승과 다시 수호전을 하는 것은
  서사상 `연습을 받아 주는 것`으로 처리한다.

### 5.4 깊은 꿈 — 합동 수호전의 서사

규칙·수치·보상은 `docs/guardian_raid_design.md`가 단일 원본이다. 이 절은 그
콘텐츠의 세계관 근거만 정한다.

- 수호짐승은 원래 잠이 많다. 아주 깊이 잠들면 꿈속에서 자기가 지키던 것을 평소보다
  더 꼭 끌어안는다. 그럴 때 관리인은 혼자 깨우지 못해 여섯 친구를 부른다. 꿈의
  장벽 세 겹(겉꿈·선잠·깊은 꿈)을 차례로 열고 짐승을 **살며시 깨워 주는 것**이
  합동 수호전이다.
- 깨어난 짐승은 개운해하며 끌어안았던 것을 스스로 내려놓는다. 그 순간의 장면이
  이야기 도감 `꿈 발견 장면` 4종으로 남는다.
- **여섯 부름말의 유래** — 관리인들은 오래전부터 도와주러 온 친구들을 여섯
  부름말로 불렀다. 막아서는 친구는 `지킴`, 일으키는 친구는 `돌봄`, 힘을 이어 주는
  친구는 `이음`, 짐승의 마음을 가라앉히는 친구는 `달램`, 어둠 속에서 알아보는
  친구는 `밝힘`, 이야기를 닫아 주는 친구는 `매듭`. 스킬 성장 설계서 6.6의 역할
  체계는 이 부름말을 그대로 쓴다. UI의 역할 배지는 게임 용어가 아니라 세계관
  언어다.
- 꿈 발견 장면 4종은 미해결 질문(10.2)의 힌트를 하나씩 담는다. 장부지기의 꿈에는
  부치지 못한 답장(OQ-1), 메아리지기의 꿈에는 낯선 이름을 부르는 목소리(OQ-3),
  씨앗지기의 꿈에는 새벽 병이 열리는 아침(OQ-4), 기록지기의 꿈에는 푸른 잉크로
  쓰는 손(OQ-2)이 스친다. 어느 힌트도 답을 확정하지 않는다.
- 꿈속에서도 1.2의 여섯 규칙이 그대로 적용된다. 악몽·괴물·죽음은 꿈이라는 이유로도
  등장하지 않는다.

### 5.5 엉킴 — 일반 전투의 상대

스테이지 전투(`docs/expedition_stage_redesign.md` 3.3)의 상대인 엉킴의 세계관
근거다.

- 엉킴은 관리인의 손이 못 닿는 사이 **엉켜 버린 지역의 물건들**이다. 장부 뭉치가
  뒤엉키고, 메아리가 매듭지고, 별가루가 얽힌 것이지 어떤 악의·오염·감정의 산물이
  아니다. 1.2의 제1 규칙(나쁜 감정은 없다)이 일반 전투에도 그대로 적용된다.
- 전투는 무찌르기가 아니라 **풀어 주기**다. HP 0 연출은 엉킴이 스르르 풀리며 원래
  물건 하나로 돌아가는 것이고, 문구는 `엉킨 장부가 풀려서 제자리로 돌아갔어요`
  방향으로 쓴다. 소멸·격파·처치 언어는 1.3의 금지 표에 따라 쓰지 않는다.
- 엉킴이 자꾸 생기는 이유는 관리인의 결핍(5.2)과 같은 뿌리다. 혼자 다 돌보지
  못하는 방이 넓기 때문이고, 파티의 스테이지 진행은 관리인의 일손을 나누는
  이야기다. 지역 완주 시 관리인이 이를 한 문장으로 인정한다.
- 엉킴은 개체 서사를 갖지 않는다. 이름·기억·대사가 없고 도감에도 종류만 기록된다.
  개체에 애착을 붙여 놓고 풀어 버리게 하는 감정 조작을 만들지 않기 위해서다.
- 큰 엉킴(중간 보스)은 수호짐승과 무관하다. 짐승이 흘리거나 만든 것이 아니며,
  짐승과 엉킴을 잇는 배후 설정을 만들지 않는다. 이 세계에 배후는 없다.

## 6. run_thread 12종 카탈로그

### 6.1 규격과 선택 규칙

- thread 하나는 `로그라인 + seed 2변형 + echo 2변형 + payoff 3변형`으로 구성한다.
  seed·echo 본문은 90자, payoff는 140자 상한을 따른다.
- 배치와 기능은 플레이어 경험 설계서 9.1을 따른다. seed는 첫 2개 사건 안, echo는
  중간 분기 한쪽, payoff는 목표 또는 선택 발견에 붙는다.
- seed·echo 변형은 지도 템플릿에 따라 콘텐츠 팩이 결정적으로 지정한다. 같은
  템플릿·같은 thread면 항상 같은 변형이 나오며 난수를 쓰지 않는다.
- payoff 변형은 선택 기억 `approach`에 결정적으로 매핑한다.

```text
payoff_variant =
  careful     if approach == careful
  bold        if approach == bold
  relational  if approach == relational
  # approach == mixed:
  run에서 가장 많이 기록된 계열, 동수면 마지막 확정 선택의 계열
```

- `kept_promise`·`discovery_focus`는 payoff 본문 안의 한 구절 치환에만 쓴다.
  치환 구절은 콘텐츠 팩의 닫힌 목록이며 자유 조합하지 않는다.
- 사용자가 고르지 않은 접근의 결말을 이미 겪은 것처럼 쓰지 않는다. 각 payoff는
  해당 접근이 실제로 한 행동만 서술한다.
- thread 배정은 미완성 thread를 우선 제안하되 강제하지 않고, 같은 thread를 최근
  5회 안에 반복하지 않는다.
- 모든 thread는 `발견 연결`(관련 도감·장면)과 `다음 흔적`(다른 thread·아크로
  이어지는 고리)을 하나 이상 가진다. 외딴 thread는 만들지 않는다.

  파티를 향한 응답이 기준 리듬이다.

### 7.3 등급이 사는 표현량의 분배

스킬 성장 설계서 5.2는 등급이 `전용 대사·관계 beat 수`를 산다고 정했다. 그 실체를
아래로 고정한다. **필수 서사(thread·관리인 사건·유대 4단계·관계 beat 기본
3종·짝 대화 1장면)는 전 품종 동일**하고, 등급은 선택 열람형 회상만 더 산다.

| 등급 | 품종 | 전용 회상 장면 | 관리인 접점 대사 |
|---:|---|---:|---:|
| 1 | 뽀또 | 2 | 1 |
| 2 | 로제온, 블루미 | 각 3 | 각 1 |
| 3 | 가시로, 시들잎 | 각 4 | 각 2 |
| 4 | 여우비, 그림싹, 하루 | 각 5 | 각 2 |
| 5 | 별솔, 설화 | 각 6 | 각 3 |
| 합계 | — | **43** | **19** |

- 회상 장면은 캐릭터 상세에서 다시 보는 1~3문장짜리 기록이다. 유대 단계·첫
  선두·첫 수호전 같은 개인 이정표에서 열린다.
- 접점 대사는 7.2의 지역·인물 접점에서 재생되는 전용 문장이다. 지역 재방문 시
  조건 없이 순서대로 열린다.
- 어떤 회상·접점도 XP·씨앗·판정·전투에 영향을 주지 않으며, 미보유 품종의 회상은
  상점에서 개수만 공개하고 내용은 보유 후에 연다.

## 8. 관계 서사

### 8.1 관계 beat 360

- 조합 수는 같은 품종 조합을 포함한 `15×16÷2 = 120`이다. species 두 개는 code
  사전순으로 정규화해 저장한다(탐험 설계서 13장 승계).
- 각 조합은 `departure`(출발), `camp`(쉼터), `return`(귀환) 세 beat를 가진다.
  120 × 3 = 360이다. 알 수 없는 구버전 품종은 공용 문장으로 안전하게 대체한다.
- beat 하나는 상황 지문 1문장 + 대사 2줄(각 품종 말투)로 구성한다. 지문 90자,
  대사 각 60자 상한이다.
- 성장형 결(6종)은 대사의 어미·리액션 슬롯만 바꾼다. 7.5의 3층 조합 규칙과 최근
  5회 중복 금지를 그대로 따른다.
- 정원 길잡이는 관계 beat의 대상이 아니다(9장).

### 8.2 야영지 짝 대화 105

- 서로 다른 품종 두 명이 같은 쉼터에 도착할 때 열리는 핵심 장면 1개씩,
  `15×14÷2 = 105`장면이다. 같은 품종 조합은 일반 beat가 담당하고 짝 대화는
  만들지 않는다. 이후 장거리 개척도 같은 원고와 노출 원장을 재사용한다.
- 핵심 장면은 야영지에서 재생되는 4~6줄 대화이며, 두 품종의 개인 질문(7.2)이
  스치는 지점을 반드시 하나 포함한다.
- 같은 조합의 두 번째 개척부터는 핵심 장면을 반복하지 않고 2줄짜리 회상 변형을
  보여 준다.

### 8.3 대표 원고 예시

아래 예시는 원고의 기준 품질과 리듬을 고정하기 위한 **검수 기준 샘플**이다.

`departure` — 뽀또 × 설화

> 출발 준비를 하는 두 사람. 설화가 명단을 펼친다.
> 설화: 출발 전 점검. 물통, 지도, 표본함… 그리고.
> 뽀또: 뽀또! 뽀또도 챙겨야 해!
> 설화: …명단 첫 줄에 이미 적어 뒀어.

`camp` — 가시로 × 블루미

> 쉼터에서 다음 방 순서를 정하는 중.
> 블루미: 다음 무대… 아니, 다음 방은 내가 먼저 들어갈게!
> 가시로: 맘대로 해. …발밑의 가시는 내가 미리 치워 뒀을 뿐이야.

`return` — 여우비 × 하루

> 귀환길, 하루가 수첩을 덮는다.
> 하루: 오늘 발견 목록, 열두 개. 수첩에 다 적었어.
> 여우비: 후후, 열세 번째는 비밀이야. …농담. 네 수첩 마지막 장에 끼워 뒀어.

`camp` — 뽀또 × 뽀또 (같은 품종 조합)

> 두 뽀또가 서로의 화분에 새싹 스티커를 붙여 준다.
> 뽀또: 내가 형이야! 스티커 먼저 붙였으니까!
> 뽀또: 그럼 나는… 내일의 형 할래!

장거리 짝 대화 — 시들잎 × 별솔

> 야영지의 밤. 별솔이 밤하늘에 대고 변환식을 연습한다.
> 별솔: 별자리 세 번째 줄… 관객이 없으니 영 힘이 안 나네.
> 시들잎: 으으… 밤 근무는 내 담당인데. …오늘만 첫 관객 해 줄게.
> 별솔: 좋아, 특등석이야! 잠들면 안 돼?
> 시들잎: 그건… 약속 못 해.

### 8.4 반복과 신선함

- core 짝 대화는 계정당 한 번만 노출한다. 현재 파티의 core를 모두 본 뒤에는
  그 파티 안에서 가장 오래전에 본 조합의 2줄 reprise를 고른다.
- 관계 콘텐츠는 pack마다 "이번 pack의 조합" 6개에 회상 변형 1개씩을 추가해 오래된
  조합이 유물이 되지 않게 한다. 새 품종이 추가되면 그 품종의 beat 전 조합과 짝
  대화가 같은 pack에 함께 실린다. 부분 출시로 빈 조합을 만들지 않는다.

## 9. 정원 길잡이의 자리

- 길잡이는 온실이 흙과 이슬로 빚어 보내는 **정원 그 자체의 손**이다. 탐험이 끝나면
  온실로 스며들어 돌아가므로 개인 이름·기억·유대를 갖지 않는다. 이것이 길잡이에게
  고유 스킬·개인 기록·관계 beat가 없다는 기존 계약의 세계관 근거다.
- 길잡이 대사는 1인칭 없는 안내 문장 톤으로 통일한다. `이쪽 길이 안전해 보여요`는
  가능하고 `제가 어릴 때는요` 같은 개인 서사는 금지다.
- 길잡이를 수집·성장·명명 대상으로 만들지 않는다. 훗날 길잡이에게 서사를 붙이고
  싶다면 그것은 새 품종 캐릭터로 출시해야 하며, 기존 길잡이 슬롯의 무료·무제한
  계약을 건드리지 않는다.

장거리 개척 3단계(탐험 설계서 9.8)의 이름과 구조를 그대로 쓰고, 각 단계에 서사

|---|---|---|---|
| 우물 너머 답사 | 온실 담장은 끝인가, 시작인가 | 담쟁이에 덮인 낡은 문설주 발견 | 문설주의 문양이 서고 우편(OQ-1)의 소인과 같다 |
| 별빛 종단 | 들판의 별빛과 보관고의 별빛은 같은 빛인가 | 들판의 별빛이 땅속 빛의 뿌리로 이어짐을 확인 | `roots_of_light`가 온실 밖까지 이어진 큰 지도의 일부였다는 사실 |
| 온실 바깥 개척 | 두 번째 온실에는 누가 있나 | 두 번째 온실의 문 앞 도착 | 문은 잠긴 것이 아니라 노크를 기다린다. 문이 열리는 것은 다음 pack이다 |

- 개척 출발 연출은 `vault_bottled_dawn`의 새벽 병에서 빛 한 줌을 나눠 받는
  장면을 쓴다. 시계지기가 말한 "떠나는 날"의 약속을 회수하는 연출이다.
- 3단계 도착점은 클리프행어지만 불안형이 아니라 기대형이다. 문 너머에서 따뜻한
  불빛과 물 주전자 소리가 새어 나오는 것까지 보여 주고 멈춘다.
- v1 출시 범위는 3단계 도착점까지다. 문이 열리는 순간과 그 너머는 v1에 넣지 않는다.

### 10.2 미해결 질문 원장

떡밥을 감으로 관리하지 않는다. 모든 장기 질문은 아래 원장에 등록하고, 등록된
질문은 취소하지 않는다.

| code | 질문 | 심어 둔 곳 | 답의 공개 |
|---|---|---|---|
| `OQ-1` | 말라붙은 우편의 발신인은 누구인가 | `archive_dried_postcard`, 개척 1단계 문설주 | 이후 pack |
| `OQ-2` | 관측 일지의 두 번째 필체는 누구인가 | `observatory_shared_margin` | 이후 pack |
| `OQ-3` | 메아리가 남긴 처음 듣는 이름은 누구인가 | `well_twice_returned_name` | 이후 pack |
| `OQ-4` | 새벽 병은 언제, 어디서 열리는가 | `vault_bottled_dawn` | 개척 출발 연출에서 부분 회수, 완전 회수는 이후 pack |
| `OQ-5` | 두 번째 온실에는 누가 사는가 | `observatory_second_door`, 개척 3단계 | 이후 pack |

- OQ-1·OQ-2·OQ-3은 같은 인물일 수도, 아닐 수도 있다. v1 원고는 어느 쪽으로도
  확정하지 않으며, 확정은 원장 갱신과 함께만 한다.
- 한 pack에는 새 질문을 최대 2개만 등록하고 기존 질문의 답을 최소 1개 공개한다.
  질문이 쌓이기만 하는 운영을 금지한다.
- 답은 콘텐츠 추가로만 공개한다. 확률·유료 상품·기간 한정 이벤트 뒤에 두지 않는다.

### 10.3 pack 역류 규칙

새 지역·새 pack이 나올 때 기존 네 지역에 사건 4개를 역류시키는 운영 계약(스킬
성장 설계서 14.5)에 서사를 얹는다. 역류 사건 4개 중 **최소 1개는 미해결 질문
원장의 진행**이어야 한다. 새 지역에서만 이야기가 전진하고 초기 지역이 유물이 되는
것을 막는 장치다.

## 11. 문장 규격과 로컬라이제이션

### 11.1 key 체계

| 종류 | key 형식 |
|---|---|
| thread beat | `story.thread.{thread_code}.seed.{a\|b}` / `.echo.{a\|b}` / `.payoff.{careful\|bold\|relational}` |
| payoff 치환 구절 | `story.thread.{thread_code}.payoff.mod.{promise\|focus}.{...}` 닫힌 목록 |
| 관리인 대사 | `story.keeper.{keeper_code}.{event\|revisit_1..3\|relic}` |
| 수호전 문구 | `story.beast.{beast_code}.{enter\|opened\|retreat}` |
| 관계 beat | `story.bond.{species_a}__{species_b}.{departure\|camp\|return}` species는 code 사전순 |
| 짝 대화 | `story.duet.{species_a}__{species_b}.{core\|reprise}` |
| 회상·접점 | `story.memoir.{species}.{n}` / `story.affinity.{species}.{n}` |
| 미해결 질문 | `story.openq.{oq_code}.{hint_n\|answer}` |

관리인 code는 `root_librarian`, `wave_bellringer`, `germination_clockkeeper`,
`ringcount_observer`, 수호짐승 code는 5.1의 표를 쓴다.

### 11.2 문장 규격

- 상한: 사건·지문 90자, 선택 label 24자, 결과·payoff·진화 문구 140자, beat 대사
  한 줄 60자. 탐험 설계서 13.2의 규칙(환경 먼저, 감정 단정 금지, detour는 안전한
  해결)을 전 채널에 적용한다.
- 내레이션 어미는 `~어요/에요`로 통일한다. 캐릭터 대사만 품종 말투를 쓴다.
- 1.3의 canonical 용어만 쓴다. 금지 표현은 CI 사전 스캔 대상이다.
- 숫자·계수·확률·성능 표현은 스토리 문장에 넣지 않는다. `조금`, `한 번`, `한 줌`
  같은 정성 표현만 허용한다.
- 문장은 전부 localization 리소스로 관리하고 이미지·코드에 합성하지 않는다.

## 13. 콘텐츠 validator

스토리 콘텐츠 팩 CI가 다음을 강제한다. 하나라도 실패하면 배포하지 않는다.

- thread 12종의 code가 6장과 일치하고, `archive_breathing_ledger`의 기존 3문장이
  seed A·echo A·payoff(careful) 자리에 byte 단위로 보존된다.
- 각 thread에 seed 2·echo 2·payoff 3 변형이 정확히 존재하고 문자 상한을 지킨다.
- payoff 매핑이 `approach` 네 값 전부에서 결정적이며, 스토리 경로에 난수 호출이
  0건이다.
- 일기 본문·감정명·감정 점수·자유 입력을 읽는 스토리 코드 경로가 0건이다.
- 1.3 금지 표현·감정 단정 문형(`오늘 슬펐으니` 류)이 사용자 노출 문구에서 0건이다.
- 관계 beat가 120조합 × 3으로 정확히 존재하고 species 순서가 사전순으로 정규화돼
  있다. 짝 대화는 105조합 × core/reprise가 존재한다.
- 회상 43·접점 19의 분배가 7.3 표와 일치하고, 어떤 회상·접점도 판정·보상 코드를
  참조하지 않는다.
- 발견 장면 32종이 전부 thread 또는 미해결 질문과의 연결 표기를 가진다.
- 미해결 질문 원장에서 삭제된 질문이 0건이고, pack diff 기준 새 질문 ≤2·답 공개
  ≥1 규칙을 지킨다(v1 초기 등록은 예외).
- 위기 지원 활성 상태에서 새 thread·회상 노출 경로가 0건이고 열람 경로는 유지된다.
- 모든 story key가 실제 리소스를 가리키고, 하드코딩된 한국어 스토리 문장이 코드에
  0건이다.

## 14. 테스트 계약

- unit: payoff 매핑 결정성(approach 4값 × kept_promise × discovery_focus 전수),
  thread 배정의 최근 5회 중복 금지, species 사전순 정규화, 문자 상한 검사기.
- integration: thread 배정 → seed/echo 노출 → payoff 스냅샷 저장 → 홈 회상
  1회 재생의 전 흐름. 수확·회향 뒤에도 유대·beat·회상이 식물 인스턴스에 유지되는
  것. 위기 지원 게이트. 기존 도감 24종 발견 상태 마이그레이션 보존.
- widget: beat·thread 문장이 사건 화면의 정보 순서 계약을 밀어내지 않는 것,
  스크린리더가 지문·대사 화자를 구분해 읽는 것, 회상 재생이 자동 1회로 끝나는 것.
- 콘텐츠 리뷰: 정서 안전 체크리스트(2장)와 표현 검수를 전 원고에 사람 리뷰로
  수행하고, 통과 기록을 pack에 남긴다.

## 15. 완료 판정표

| 항목 | 판정 기준 |
|---|---|
| 한 판이 한 편이다 | 모든 일반 run에 thread가 배정되고 seed→echo→payoff가 실제로 순서대로 노출된다 |
| 결말이 내 것 같다 | payoff가 approach를 정확히 따라가고, 사용자가 결과 화면에서 그 연결을 읽을 수 있다 |
| 세계가 이어져 있다 | 발견 32종·thread 12종·아크 3단계 사이의 연결 고리가 문서와 1:1로 구현된다 |
| 수호자가 무섭지 않다 | 수호전 진입·개방·귀환 문구가 5.3 계약을 지키고 죽음·패배 언어가 0건이다 |
| 캐릭터가 자란다 | 스킬 tier 이름·진화 문구·개인 질문·유대 대사가 같은 아크를 말한다 |
| 관계가 살아 있다 | 360 beat + 105쌍의 core/reprise가 전 조합 존재하고 core가 반복되지 않는다 |
| 떡밥이 빚이 되지 않는다 | 미해결 질문 5건이 원장에 있고 취소·확률·과금 뒤 공개가 0건이다 |
| 일기가 안전하다 | 스토리 변수에 일기 파생 값이 0건이고 분석 이벤트에도 없다 |
| 읽지 않아도 손해가 없다 | 스토리 전부를 건너뛴 계정과 전부 본 계정의 XP·씨앗·진행이 동일하다 |
| 자국어 심사를 통과한다 | 전 문구가 story key로 관리되고 문자 상한·금지 표현 검사를 통과한다 |

## 16. 금지하는 지름길

- 사용자 일기·감정 데이터를 "개인화 스토리"의 입력으로 쓰는 것
- 런타임 LLM으로 대사·지문을 생성하거나 검수 없는 문장을 배포하는 것
- payoff·회상·짝 대화 노출에 숨은 확률을 넣는 것
- 스토리 진행에 XP·씨앗·기간 한정·유료 조건을 붙이는 것
- 수호짐승을 처치·사냥·보스 언어로 광고하는 것
- 미해결 질문을 원장 등록 없이 심거나, 등록된 질문을 조용히 폐기하는 것
- 새 pack의 이야기를 새 지역에만 실어 기존 지역·기존 thread를 유물로 만드는 것
- 관계 beat를 일부 조합만 출시해 빈 조합을 만드는 것
- 길잡이에게 이름·개인 서사를 붙여 수집 대상으로 만드는 것
- 등급 회상 수량을 성능 격차의 완곡한 표현으로 확대하는 것
- 이별·상실 소재로 감정을 자극해 리텐션을 만드는 것
- 스토리 문장을 이미지에 합성하거나 코드에 하드코딩하는 것
